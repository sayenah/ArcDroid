## JFD / ADFFS evidence (S17–S18, Fable; host only; private evidence in the S17 scratchpad `jfd/` and S18 scratchpad `adffs/`; counts and words only)
- **Root cause (S17):** JASPP JFDs are meant to be booted by ADFFS from a boot Obey script (memory setup, loading, `MEMA`/`MemoryA` patches guarded by `ADFCRC`, removal of original protection/auto-configure steps), not from the disc's own `!Boot`. 130 of the 233 library JFDs embed a script; of the 22 self-booting titles that did not start on the Odin3 (S14): 15 fail natively for want of the script (3 × `Disc error 10` on sectors absent from the dump, 3 × "Unprotect the disc" write attempts, 6 × `*` prompt/hang, 2 × BASIC errors, 1 × stuck at its own loading text), 4 start given a 45–60 s dwell, 3 sit on the desktop (the ADF and the two JFDs with no script). The S13/S14 sweep classifier (> 97 % black = `BLACK`, 40 s dwell) mislabelled text screens and dark titles — tooling defect, not product.
- **ADFFS 2.88 package (S18; Founder-supplied zips on the dev Mac Desktop, full and lite; forum thread `https://forums.jaspp.org.uk/forum/viewtopic.php?t=722`, not fetched — HTTP 403 is not worked around):** requires RISC OS 3.10+; separate 34 228-byte IOC module for OS < 3.5, identical in both zips (help string `ADFFS 2.88 (28 Mar 2026) IOC`); **no licence or redistribution statement anywhere**; `!ADFFS/obey` is a zip of 397 scripts keyed by disc id; library coverage: 77 JFDs have built-in + embedded (all 77 differ; built-in is the maintained one), 12 built-in only, 53 embedded only, 91 neither; the 22 non-starters: 15 both, 4 embedded only, 3 neither. Resources referenced by the 527 known scripts: `trackers.*` (QTMModule 98, MusMod2 51, TrackerMod 25, ExSound 22, DTT 11, others ≤ 4, TimPlayer 3), `extras.JoyMod` 37, `extras.LZWD*` 5. Runtime + `obey` + all referenced resources except the 345 KB TimPlayer = 22 files, 637 952 bytes on 1024-byte boundaries + directories, of 819 200. Zip uses deflate (lite also stored), general-purpose flag bit 1 only, RISC OS metadata in the `AC`/`ARC0` extra field.
- **SHA-256 of the runtime members (identical in both zips):** `ADFFS` `23256f9c73ea49a6c51d21844b2d07eaaa235bea41258b7a92e05ff488e77cae`; `SetVars` `266617cf3f8c4f541730d9704dd9f390b71e00318e96a128f4b3dc609571b831`; `3rdParty/CLib` `2935eaa8bf7111ee726496eb2764e56206bdeed0cb220e50c4ed33c4acf9d849`; `3rdParty/CallASWI` `a73f88eac988c9057d0b46117279166f4c2cfda4e92574f385b80d57440a27fa`; `3rdParty/ZLib` `6a012e8fc0e480c2b5cb88b98f4249303c88e7d2f32bfe7b05c8e1fc3e668e07`; `3rdParty/BootCmds` `96bb091eb6fedc96a32da876454f5e9f8aa53426d141bd20b4763a15c0f0efdc`.
- **Probe result:** scratch 800 K D-format disc (built with `tests/generate_fixtures.py` helpers) carrying the minimum ADFFS files + one private JFD as a `&FCE` file; launcher copied `!ADFFS` to a 640 K RAM disc, was started by `Filer_Run` from RAM, replayed ADFFS's start-up logic with the LCD helper off, then `ADFMount` → `ADFS`/`NoDir`/`NoLib`/`NoURD`/`Dismount :0` → `ADFBootFloppy`. Of the 13 non-starters that fit the probe disc: **10 reach their title screen, menu or gameplay** (30–60 s emulated, mostly the probe's own floppy-to-RAM copy), 1 add-on data disc correctly asks for its game disc, 1 stopped on the omitted `extras.JoyMod`, 1 (no script of either kind) ended on an empty grey screen. No core or engine change was needed. After the mount `Cat ADFS::1.$`, `Type` and `Copy` of a drive-1 file all succeed.
- **JFD header flags (+304)** are still decoded by nobody: bit 0 write-protected, 1 read-write with deltas, 2 protect CMOS, 3 protect modules, 4 hide hourglass, 5 requires Shift-Break, 6 video-memory remap; bits 8–13 ARM compatibility; bits 16–22 RISC OS compatibility (facts from the documentation comment in MAME `jfd_dsk.cpp`; no code used). ADFFS honours them itself on the ADFFS path.
- **ADFFS platform facts established in S18 (keep):** loading the ADFFS module closes every open ADFS handle (a launcher read from a floppy dies with `Handle is either illegal or has been closed`) — run it from RAM, started by `Filer_Run`; the module executes `Obey ADFFS:!RunTypes <n>` and `Obey -c ADFFS:!fixObey` and **writes the selected script to `ADFFS:!Obey`**, so its directory must be guest-writable; `ADFFS$LCDGM` must be `N` (unset or `Y` ends in a garbled `…nager:Sprites24` error box, which is also what any failing command inside `ADFBootFloppy` looks like); module titles/versions: `SharedCLibrary 5.17`, `CallASWI 0.02`, `ZLib 0.05`, `BootCommands 0.00`, `ADFFS`; numeric variables need `SetEval`; the do-nothing aliases must pass parameters (`ADFDoNothing %*0`); RAM disc is sized with `ChangeDynamicArea -RamFsSize <n>K` and `Copy` takes option letters (`~C~VRFQ`); the `obey` library also holds auxiliary members named `F` + 7 digits + a letter; Python's `zipfile` on Windows rewrites `\\` in member names to `/` (fixtures must patch raw name bytes); after `ADFMount`, drive 1 stays readable; ADFFS reads a large image file in two full passes at floppy speed.
- **Parked:** the clean-room ADFFS-command layer (former Option A; ≈ 30 commands for the built-in vocabulary) is a follow-on candidate, decided on demand; multi-disc ADFFS support needs the sibling images reachable as files after drive 0 is taken over (no design yet).
