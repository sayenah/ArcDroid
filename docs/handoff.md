## Objective and governing requirement
Slice 2b launch automation faults on Android RetroArch. On the AYN Odin3 (Android 15, RetroArch 1.22.2, `main` = `de4b975` NDK build) every disc that receives a drive-1 launch helper shows a black screen from the first frame. Root cause, verified on the device: after each frame the engine flushes every open floppy handle (`engine/arcdroid_engine.c:458` → `adf_flush_all` in `engine/arculator/src/disc_adf.c` → `arc_io_flush_file` in `libretro/arc_io.c` → `retro_vfs_interface.flush`). The helper is mounted read-only (`adf_set_writable(1, 0)`, opened with `RETRO_VFS_FILE_ACCESS_READ`). RetroArch 1.22.2's VFS flush is `fflush(stream->fp)` (`libretro-common/vfs/vfs_implementation.c`, file opened with `fopen(path, "rb")`), and bionic's `fflush` on a read-only stream returns -1 with `EBADF` (NDK probe run on the Odin3: `fopen("rb")`+`fflush` → -1 EBADF with or without a prior read; `"r+b"` → 0). The engine treats the failure as fatal (`Unable to flush the staged floppy image`), so `arc_engine_run_frame` returns false for the rest of the session. The host and Windows harness VFS implement `flush` as `fflush` on glibc/macOS/UCRT, where it returns 0 on read streams, so `ctest`, the sanitizer job and the Windows probe could not observe the fault. Governing: PRD FR-2 (Android first-class), FR-24…FR-27; D-030; protocol §11, §12.

## Scope
- **R-71 Engine/bridge invariant.** Never flush a handle that was opened read-only. The per-frame sweep (and any other flush) covers only drives whose handle was opened for writing: the drive-1 helper is always read-only; drive 0 is read-only when the write policy is off or the image had to be opened read-only. A flush failure on a *writable* handle stays fatal (Slice 1 data-loss containment). Detection is by the handle's open mode (tracked in the VFS bridge or equivalent), not by drive number.
- **R-72 Harness fidelity.** The host harness VFS (`tests/libretro_harness.c`) and the Windows load harness (`tests/windows_load_harness.c`) must return -1 from `flush` on a handle opened with `RETRO_VFS_FILE_ACCESS_READ`, matching RetroArch-on-bionic, so the launch and read-only-media paths fail on `main` and pass with R-71. Adjust the `tests/jfd_controller_tests.c` stub only if it would otherwise mask the same case.
- **R-73 Regression coverage.** Deterministic host tests: (a) a launch-helper session (generated launch fixture, helper in drive 1) runs ≥ 500 frames with fields completing and no fatal message, and still reaches the fixture pattern with the existing direct-boot signature equality; (b) `arcdroid_disk_writes = off` with the generated ADF completes frames; (c) an injected flush failure on a writable handle still raises the fatal message (existing `fault_flush_substring` path or equivalent).
