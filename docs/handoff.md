## Slice 12b work order — JFD identification track: presented sector IDs for omitted free slots (G5)
**Objective.** JASPP's imager omits the sector IDs of unused sectors. When such sectors fall on cylinder 0 head 0 — the only track-side RISC OS ADFS reads to identify a floppy's format — ADFS counts too few IDs (3 instead of 5 on D-format, 8 instead of 10 on F-format), derives the wrong sectors-per-track and the disc appears as "Broken directory"/"Disc error"/a misread `!Boot`. Six double-density disc-1 captures on the native path (idx 30, 48, 67, 77, 100, 149) and the quad multi-image sets 78 and 84 fail this way; the eleven single-image quad titles cannot be catalogued natively at all (they boot only through user-supplied ADFFS, D-066/D-067). Fix: ArcDroid's native JFD reader presents each omitted standard slot of track-side 0 as an **ID-only sector** (READ ADDRESS/READ ID see the ID; a data read keeps Record-Not-Found — no data is invented) when the disc's own valid FileCore map proves that slot free. This is an ArcDroid compatibility policy derived from the disc's own map — a structural rule of the media, no title knowledge (D-039, Founder S33) — not recovered capture truth. Governing: PRD P-3, P-7, FR-10, FR-24, FR-25, FR-52, FR-55; D-066/D-067 as amended by D-089; D-075–D-081 (C-11/C-11c stay); D-073, D-085.

**Scope.**
C-1 **Presentation rule.** For every JFD image served by ArcDroid's native reader — any header flags (RW, WP, unflagged, legacy, `layout-unsupported`), any `Disk Writes` mode, any machine — the reader presents omitted standard slots of **track-side 0 only** (cylinder 0, head 0, the identification track-side) as ID-only sectors when **all** of the following hold, evaluated once at native preparation by a **dedicated base-only proof operation** over the **original captured base payloads only** (never a created slot, a committed record, an overlay replacement or a presented slot; launch discovery's own parsers and primary-copy policy stay untouched) and frozen until the next native preparation: (a) **format and map**: FileCore identification succeeds with the existing probing order (old map D, new map E, F) from captured payloads and yields the format's standard schedule — D/E: IDs 0–4, 1024 bytes, density 2; F: IDs 0–9, 1024 bytes, density 4 — with at least one **valid map copy**: old map: both checksummed halves, ordered non-overlapping positive extents within the disc, and a declared size that the existing parser does not have to clamp (a clamped declaration declines G5 while discovery keeps its behaviour); E: copies 0 and 1 examined independently (backup-only validity admits); F: each complete multi-zone copy (primary, backup) validated independently, never assembled from zones of different copies, at most eight zones per copy. An unreadable or malformed copy supplies no evidence; a structurally valid copy whose layout (sector geometry, disc size, map-bit scale, fragment-ID width, zone count and spare, addressing flags) conflicts with another valid copy or with the boot/disc record disqualifies the whole plan; (b) **regularity**: every stored descriptor on track-side 0 is a standard sector of that schedule (size, density, `id` < schedule, unique ID, payload-owning, no shared/aliased payload, no ID-CRC-bad, no data-CRC-bad, no slow flag, no captured ID-only descriptor), the stored ID set is a **strict, non-empty subset** of the schedule, and no two captured descriptors share a normalised rotational position (the parser maps both 0 and 200 ms to phase zero; coincident positions would keep READ ID from enumerating the captured schedule); (c) **free space, proven positively**: every byte of the slot `[slot·size, (slot+1)·size)` lies below the declared disc size and inside free space in **every** valid copy — old map: covered by the union of validated adjacent free extents; new map (E/F): within fragments of the validated free chain, using the existing zone boundaries and zone-to-disc addressing — never by inverting an allocation mask or by the whole-track free view; an allocated, defect or beyond-disc byte in any valid copy disqualifies the slot; (d) **placement** (C-2) succeeds for every missing slot. Admission is **all-or-nothing** for the track-side: any failed precondition presents nothing (today's behaviour, captured descriptors untouched) and is logged with its reason (C-4); partial presentation is never done (RISC OS would still miscount). 23 disc 2 receives no presentation.

C-2 **Placement and controller semantics.** A presented slot gets a deterministic base-derived rotational position by the same rule as C-11 version-1 placement, parameterised by the schedule's transfer interval (36 352 µs for DD/1024, 18 176 µs for quad/1024) within the 200 000 µs revolution: timed track-side → after the nearest lower present ID, skipping every occupied interval incl. index wrap (C-11's tolerance of captured interval overlap is kept; only coincident starts are refused by C-1(b)); untimed track-side → appended after the last packed descriptor in ascending ID order; captured starts are never moved (no salvage by moving captured sectors); unplaceable → nothing presented. **Invariant:** on a writable image whose C-11 plan covers track-side 0, the presented position of each slot equals `creation_time` before and after writes and reloads (one placement function, one set of inputs, asserted by tests; P-DD5 results unchanged). The presented sector has the standard ID field (C = 0, H = 0, R = id, N = 3) with a good ID CRC and **no data**. **Effective view and enumeration:** the shared effective view exposes three independent facts — ID visible, readable data (a non-null pointer), write-eligible — and enumerates every captured **descriptor ordinal** of the track-side (up to the parser's 256, protection duplicates included, never deduplicated or capped at the schedule) followed by **at most one candidate per omitted standard slot** that combines the G5 and C-11 capabilities of that slot (a presented slot never duplicates a C-11 slot, never turns a captured ID-only descriptor into a writable creation, and stays exactly one candidate before and after allocation or creation); captured descriptors keep precedence and ordinals, and their existing CRC, size-mismatch and refusal outcomes are preserved rather than filtered into RNF. **Transfer gates:** a guest-bound read transfer requires readable data; a guest-to-disc write transfer requires the existing C-11 write authorisation and command checks and does **not** require readable data (a prospective creation has none by design); a G5-only ID never grants write authorisation. READ ADDRESS/READ ID deliver a presented ID at its position on both controllers (WD1770 address transfer; 82C711 `sectorid`) under the schedule's density only (a wrong density never reveals it); a READ SECTOR/READ DATA that addresses it keeps searching — seeing the ID neither resets the timeout nor transfers a byte — until the controller's RNF (five index pulses on the WD1770, two on the 82C711), exactly like an ID-only base descriptor; a WRITE to it is C-11 creation on a writable image through the existing prospective path (unchanged) and write-protected refusal otherwise (unchanged); FORMAT/WRITE TRACK/READ TRACK unchanged. Precedence: a committed created record or a C-11c formatted blank at the same slot shows its data at the same position; presentation never hides data. The presented set is recomputed identically at every native preparation, reset and reinsertion; no persisted state, no store format change; `Disk Writes Off`/`visible` hide saved data as today but keep the presented IDs.

C-3 **Probe marks and unchanged behaviour.** The only semantic change to `jfd_mark_terminal_probe` is its final predicate: **lookup failure OR no readable data**; every preceding guard (map enabled and valid, density, requested cylinder/head, creation-mask membership, no committed created data) is retained, marking is never conditioned on G5 admission, the frozen free proof, ID visibility or current write eligibility, READ ID/ADDRESS never marks, repeat probes and interior probes behave as today; a mark still blocks direct creation and allocating map writes under the existing effective-map conditions (pending-map evaluation across both copies, refusal before commit, no store-failure latch, unrelated writes continue; marks survive an invalid map until validity returns, `tests/jfd_store_tests.c:555`). Later effective-map changes govern C-11c blank data exactly as today and never reposition or toggle the presented IDs. **G5 adds nothing on any other track-side** (their omitted IDs keep today's D-066/D-067 and C-11/C-11c behaviour). Unchanged: ADFFS and install paths; native/ADFFS routing and the D-084 table (single-image quads with a package still take the ADFFS path — a native reroute is a follow-up once saves are proven); launch discovery's FileCore reader and its primary-copy policy (`base_only` reads original captured payloads, `captured_only` may read committed replacements of captured descriptors, never synthetic data; an ID-only slot stays unreadable; D-087/D-088 launch behaviour unchanged); content identity (D-029), decoded hashes, overlay keys and record formats; the C-11 eligibility gate and plan (`layout-unsupported` images stay write-protected — 67, 100 and 149 gain identification, not saves), C-11c blank reads, the map-write veto, commit-before-success, damaged-store behaviour; the `JFD:`/`JFD writes:` lines; L-format 640 K captures (no presentation, existing behaviour, covered by a negative regression fixture); no state leaks between images.

C-4 **Diagnostics.** One bounded log line per native image preparation: `JFD identification: image=N native=yes|no format=D|E|F|none schedule=<n> timing=timed|untimed|none captured=<id list> presented=<id list>|none maps=<valid copy mask> reason=<code>` with a fixed reason code naming the first failed precondition (`presented`, `complete`, `irregular`, `unsupported-format`, `map-invalid`, `map-conflict`, `not-free`, `unplaceable`, `no-track`, `not-native`); no title text or payload bytes, no per-command flood.
