## Scope
S1 **Import** `src/82c711.c`, `82c711.h`, `82c711_fdc.c`, `82c711_fdc.h` from the pinned upstream commit into `engine/arculator/src/` as allowlisted files (notices preserved; each ArcDroid modification carries the standard notice); reconcile `engine/compat/82c711*.h` with the upstream declarations; update `engine/UPSTREAM.md` (allowlist + modification summary) and `CMakeLists.txt`; delete only the superseded stubs. Both files compile into both libretro targets and into every test executable that builds engine sources.
S2 **IDE**: `ide.c` is not imported. Provide `resetide` (no-op), `readide` → 0xFF, `readidew` → 0xFFFF, `writeide`/`writeidew` ignored, no IRQ (absent-bus model; hard discs are out of scope). On New-IO machines the effective boot CMOS image forces logical byte 135 bits 6–7 (IDE disc count) and bits 3–5 (ST506 count; no ST506 controller exists on these machines) to zero, and the persisted payload is normalised the same way (D-031 pattern); A3000 CMOS handling is unchanged. (Layout: bits 0–2 floppies, 3–5 ST506, 6–7 IDE — ADFS `s/Adfs05:566-590` reads the byte and shifts right three, then `s/Adfs12:250` shifts again to obtain the IDE count.)
S3 **82C711 FDC hardening** (ArcDroid modifications with notices):
- H1 Drive select: all four `params[0]&3` values are representable; drives 2/3 and any unattached drive complete with controller error status and never index `track[]`/`eot[]` (or any per-drive array) out of range.
- H2 FORMAT TRACK: bounded parameter processing (sector count 0, count exceeding the buffer, premature terminal count, incomplete parameter sequence); no write can exceed the buffer; result bytes never read below index 0.
- H3 Remove the `#ifndef RELEASE_BUILD fatal(...)` on unknown command bytes so every build takes the datasheet invalid-command path (ST0 = 0x80, result phase). Do not reclassify recognised-but-unimplemented commands without the 82C711 datasheet.
- H4 Disc-change boundaries are tested (E2); patch only a demonstrated deviation from step-pulse DSKCHG semantics.
- H5 Add `c82c711_fdc_media_change(drive)` and call it on every eject/insert/close path where `wd1770_media_change()` is called today. Contract: cancellation stops only the affected drive's transfer, clears its data request and FIQ, and leaves a readable terminal result with the completion interrupt the chip would raise for an abnormal termination; it is idempotent (a second call while idle manufactures no result and does not erase a pending one); ejecting drive 0 never disturbs an active drive-1 (launch helper) operation; teardown quiesces callbacks without creating new completion work.
- H6 Cold initialisation resets the 82C711 configuration-mode state, the full FDC state (timer detached before the storage is reinitialised) and the IOEB `hs_invert`/`ioeb_clock_select`; guest-issued FDC reset semantics stay distinct; overrun/error paths leave no FIQ asserted.
S4 **Machine descriptor table** in `core` (new): enum {A3000, A3010, A3020, A4000} with canonical name (used for options, messages and persistence), engine machine string (`a3000|a3010|a3020|a4000`), I/O class (old WD1770 / new 82C711), CPU (ARM2 / ARM250), MEMC row (MEMC1a 8 MHz for A3000; MEMC1a 12 MHz for New-IO), RAM 4096 KiB for all, compatible-OS mask (A3000 unchanged; New-IO: RISC OS 3.10, 3.11, 3.19, TEST), CMOS family (riscos3_old / riscos3_new under RISC OS 3), monitor default (Standard), joystick-port flag (A3010 only), IDE-capability flag (informational). `ArcLaunchPlan.machine` becomes the enum (canonical name retained for logs). One engine configuration entry consumes the descriptor and sets `machine`, `fdctype`, CPU/MEMC (extend `arc_set_cpu()` for ARM250: has_swp=1, has_cp15=0, CPU speed = MEMC speed) **before** memory timings and `timer_reset()`, `memsize`, `monitor_type`, `machine_type=MACHINE_TYPE_NORMAL`, `joystick_if`, and calls `c82c711_init()`/`c82c711_fdc_init()` in the upstream `main.c` order.
S5 **Options**: `arcdroid_machine {Auto, A3000, A3010, A3020, A4000}`, `arcdroid_cpu {Auto, ARM2, ARM250}`, `arcdroid_memory {Auto, 4 MB}` (unchanged). `Auto` machine = A3000 (D-013). CPU `Auto` follows the machine; an explicit CPU that does not belong to the resolved machine is an invalid-option error naming both; no coercion. Changes apply at reset/reload through the existing options-changed re-create, never from `GET_VARIABLE_UPDATE` alone; pending machine/CPU/OS options stay separate from the active descriptor and input routing until the re-create succeeds; the complete replacement plan (machine, firmware, CMOS path) is validated before the live machine is torn down, and a failed validation preserves the old machine, CMOS identity and controls; media identity, index and ejection state are preserved; the user gets the existing visible notice. Fix the existing `retro_run()` variable-update handler (`libretro/arcdroid_libretro.c:2848+`), which on an `arc_read_options()` failure still reads `updated.input_profile`/`pad`/`osk_toggle` from the unvalidated struct: stop processing that update after a validation failure.
S6 **Firmware**: F1 the descriptor's compatible-OS mask filters candidates (combined images and assembled sets) before ranking; F2 New-IO `Auto` keeps the existing relative order among 3.11/3.10/3.19; F3 messages: explicit incompatible OS → "<OS> is not supported on the <machine>"; explicit compatible OS not present → the exact missing release; `Auto` with no compatible firmware → "<machine> requires RISC OS 3.10 or later firmware; found <best available or none>"; never silently revert to A3000; F4 the project TEST OS is accepted on every machine, which requires both generated TEST ROMs (test ROM and media exerciser) to become dual-path with their fingerprints updated; a mixed firmware directory must never select an old-IO-only image for a New-IO machine.
