Governing: `docs/riscpc.md` §§4.1–4.8, 4.11, 6 (row R1); D-063, D-123, D-126, D-127, D-131, D-134, D-135, D-137; PRD FR-62–FR-68, AR-1–AR-3; protocol §10. The RPCEmu backend is reached only through the test core and a headless runner, built from the same backend sources, dispatch and libretro AV/input path, never shipped. Archimedes behaviour stays byte-for-byte unchanged.

**Scope.**
1. **Import (§4.2).** `engine/rpcemu/` holds only this allowlist, copied byte-identical from the verified tarball (`rpcemu-0.9.5.tar.gz`, sha256 `4e4624641cd1a83af275bd6da8765d4a0e5e0c83f008f059014cc24c5c33d59e`, Mercurial changeset 1369:f005be758787) in **one pristine commit**: `COPYING`, `readme.txt`, `src/{arm,arm_common,cp15,mem,iomd,vidc20,keyboard,cmos,superio,i8042,fdc}.{c,h}` (those that exist), `src/rpcemu.h`, `src/sound.h`, `src/ide.h`, `src/podules.h`. **No header-less upstream file is imported:** the `disc.h`, `disc_adf.h` and `disc_hfe.h` includes in `fdc.c` are removed together with the loader functions and loader-only tables, replaced by a fresh ArcDroid-owned typed controller interface (R1: empty drives); the `hostfs.h` and `network.h` includes and their SWI interception paths in `arm_common.c` are removed, so those SWIs take ordinary guest SWI handling. A dependency-closure check proves the compiled files include only the allowlist and ArcDroid headers. The ArcDroid patches follow in later commits, never mixed into the pristine one (Sol's sandbox cannot commit: run A delivers only the pristine allowlist, which Fable verifies against the tarball and commits verbatim; later runs are committed verbatim per run; the patch list in `UPSTREAM.md` groups changes as isolation, containment/reset, scheduler/MMU, devices/AV/input); every modified upstream file carries an ArcDroid modification notice; code adapted from any non-allowlisted upstream file (e.g. `sound.c`) keeps its original attribution and is recorded. `engine/rpcemu/UPSTREAM.md` plus a machine-readable manifest: source URL, version, changeset, tarball sha256, import date, per-file original path, sha256 at the pristine commit, quoted licence header, patch lineage; exclusions (Qt/GUI, threads, network/slirp/TAP, HostFS, CD-ROM, dynarec, podule loading/podules, FPA, `rpcemu.c`, `romload.c` incl. alphabetical concatenation and ROM patch tables, `sound.c` host threads, `ide.c`, all `disc*` files, `cmos.ram`, blank media, every binary or guest file). D-018 covers Arculator assets only. `THIRD_PARTY_NOTICES.md` updated. The tarball is not committed. An import checker verifies (a) tree = manifest, (b) given a tarball path, pristine files byte-identical, (c) every patched file carries the notice; (a) and (c) run in CI.
2. **Engine boundary (§4.1).** `arcdroid_engine.c` becomes a small dispatcher over private backend operations with exactly one active backend per session and explicit ownership during partial initialisation; the current implementation moves substantially intact into an Arculator backend with **no behaviour change**. Shared storage contracts (`ArcIdeBackend` etc.) move to ArcDroid-owned headers; CPU hooks, memory inspection, controller objects and watch globals stay private to their backend; Arculator timing/observers are not generalised. A capability record distinguishes each observer (boot watch, launch outcome, error box, disc request), floppy/media operations, helper drive, IDE, native joystick (model-specific, A3010), power-on input (the Arculator facility), CMOS persistence and serialisation. RPCEmu at R1 advertises AV, keyboard, mouse and reset only; every other entry point returns explicit failure or cleared snapshots, never stale Arculator state. Each backend has private include paths (generic names `arm.h`, `mem.h`, `ide.h` never resolve across engines). **RiscPC models live in a private backend registry selected only by the test plan; the shipping machine registry, `ARC_MACHINE_COUNT` and `arc_machine_from_name()` are unchanged.** Models: RiscPC ARM610, RiscPC ARM710, RiscPC SA-110 (64 MiB RAM, 2 MiB VRAM); A7000 ARM7500 (64 MiB RAM, no VRAM). Host allocation sized to the guest configuration (no unused 8 MiB VRAM on A7000).
3. **Isolation (§4.3).** All RPCEmu external definitions, declarations and host hooks (data included) carry one project prefix (source renaming or a forced namespace header applied only to RPCEmu translation units). An object-level symbol checker for Mach-O, MinGW PE/COFF and Android ELF inspects defined **and** undefined symbols: each engine's references resolve only to its own namespace or an explicit allowlist of ArcDroid/libc services; no common symbols; no unexpected weak definitions; no collisions. Exported dynamic symbols stay exactly today's names (strengthen `check-exports.sh` to compare exact names incl. data/weak exports); Windows dependency and Android dependency/16 KiB alignment checks retained; `check-shipping-io.sh` source discovery updated for backend targets and applied to `engine/rpcemu/` (no host threads, sleeps, file/network I/O, `getenv` or host-clock reads in RPCEmu-derived code). Test entry points absent from shipping exports.
4. **Containment (§4.3).** Inventory every compiled `fatal`, `error`, `exit` (two each in `cp15.c`, `cmos.c`, `i8042.c`), `abort`, `assert`, trap, allocation failure and potentially unbounded guest-controlled loop; classify each as **hardware-defined guest behaviour** (implement the architectural/device response — MMU aborts, documented controller results; the session keeps running), **rejected configuration** (clean start failure) or **contained emulator failure** (session fault). Remaining fatal paths use a non-returning unwind to a live backend boundary around every engine entry that can reach them; never log-and-continue; never unwind through a frontend callback (frontend input is gathered before execution; frontend callbacks happen after leaving the protected engine stack). A session fault stops all further guest/device execution and queued guest audio, reports through `arc_engine_faulted` with a clear message, never requests frontend shutdown, and leaves the session able to unload and the process able to load again; after a fault the frontend receives silence and the existing fault presentation. Start is all-or-nothing with immediate ownership tracking; no unchecked `realloc`; cleanup is non-failing and idempotent; events are quiesced before memory is freed. Every mutable global/file static (cached pointers, IRQ levels, scheduler fractions, keyboard queues, I²C transactions, raster state) is reinitialised at each fresh load. Shipping RPCEmu objects reference no `exit`/`abort`/assert-family symbol (checked). Work per `retro_run` is bounded, including with display disabled.
5. **Deterministic virtual time (§4.4).** One integer/rational scheduler in 64-bit emulated time owns CPU credit (fraction carried), IOMD timers, keyboard/mouse responses and typematic, sound DMA, raster/flyback, FDC completion (empty drives) and a slot for later IDE events; explicit schedule/cancel (re-arming with an unchanged value works); documented coincident-event order and instruction/MMIO delivery boundaries; idle advances directly to the next event. Instruction rate per model (millions of instructions per emulated second): **SA-110 100** (accepted budget, D-131); **ARM610 20, ARM710 35, ARM7500 35** provisional engineering defaults, unqualified until R4 (`docs/riscpc.md` §4.4); bounded overrides exist only in the test plan. RTC = supplied epoch + virtual elapsed time with deterministic calendar conversion (product supplies host local time once at start; the test plan pins it); no other host time, sleep, audio acceptance or presentation pacing influences guest state. Rates are never lowered to recover integration overhead.
6. **MMU correction (§4.5).** Permission/domain metadata (or equivalent validated tags) enforced on every fast path — reads, writes, instruction fetch, user-transfer instructions (LDRT/STRT class) and translated-pointer caches — for sections, large/small pages and subpages; AP with S/R bits; domain client/manager/no-access; privilege transitions; translation-table/control/DACR changes; model-specific invalidations; exact abort state (FAR/FSR for data aborts, prefetch aborts leave them; exception PC/LR/SPSR/mode). Out-of-object pointer arithmetic corrected.
7. **Video (§4.7, D-127).** VIDC20 → XRGB8888 line scanout: palette, border, cursor, depth, mode and DMA changes sampled at the scanline where they take effect; pixel-clock-derived line timing; flyback edges; DMA wrap/reload and `VIDCUR`; VRAM versus DRAM (A7000); supported depths; scanline sampling defined precisely (no pixel-cycle claim); completed lines retained independently of later guest writes. **Guest scanout progression (DMA, `VIDCUR`, flyback, timing) is fully separated from pixel storage:** presentation is bounded to **2048×2048** from the top-left of the active display, rows/columns beyond it are not stored but are still scanned, and a mid-frame size change follows the same rule; one log line when clipping first occurs; cropping never alters guest geometry, timing or DMA state. Output memory bounded and recorded. Full AV update on refresh change, geometry-only update on size change, rounding that cannot restart frontend AV drivers repeatedly; rejected notifications and missing callbacks handled.
8. **Audio and input (§§4.7–4.8).** Bounded 16-bit stereo DMA resampled deterministically to 48 kHz incl. enable/disable and rate transitions. **RPCEmu gets an exact integer sample-production/drain contract at the engine boundary** with explicit generated, frontend-accepted and discarded counts and a bounded, documented short-acceptance policy that never changes DMA interrupts or guest execution; Arculator's audio path and `retro_run` behaviour stay exactly as today. 8-bit compatibility sound unsupported (silent; logged once when enabled). Input: ArcDroid's existing arbitrated input → PS/2 set 2 and the model's mouse (quadrature RiscPC, PS/2 A7000); source retirement, held-key release, reset behaviour, pad mappings and virtual typematic preserved; mousehack SWI shortcuts disabled; no joystick on RiscPC-class models.
9. **Firmware, CMOS and absent devices.** Firmware is bytes from the plan: **2, 4 or 8 MiB only** (anything else a clean start failure); the 8 MiB ROM aperture is filled by whole-image mirroring for these power-of-two sizes, every byte defined, with boundary tests; no ROM search, concatenation, patching or fingerprinting. **CMOS initial state is a declared plan input**, one of: (a) *seed* — an explicit 256-byte image from the plan (authored tests use a committed synthetic seed; Fable's private runs use a captured one); (b) *factory capture* — empty CMOS, Delete held by an internal input from emulated time 0 for 12 s then released, run to 30 s, with evidence of the CMOS bytes the firmware wrote and a bounded failure if none were written; no firmware-address heuristics; the result can be saved as a seed by the runner. CMOS/I²C live in session memory; frontend reset keeps the current volatile CMOS, a fresh load uses the declared initial state, and both clear pending input and events. Floppy controller with empty drives completes every command per its documented no-media behaviour; IDE and expansion buses absent with defined bus responses; no hanging commands or unresolved hooks.
10. **Test entry points.** A documented plan file (text; model, rate override, firmware path relative to the frontend system directory or absolute, CMOS mode and seed path, RTC epoch, optional input script) is the only way to start an RPCEmu session: the **test core** accepts it as content (a test-only extension in a test-only `.info`, usable from native RetroArch on macOS, Windows and Android), and the **headless runner** (host, Windows, Android arm64; never shipped) runs it and emits canonical traces. Sol documents the plan format and the Android arm64 build commands for the test core and runner.
