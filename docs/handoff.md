## Slice 20 work order — omitted file-data sectors read as zeros on the native JFD path (R1′; roadmap item 2b part 1; D-105)

**Objective / governing law.** D-073, D-105 (Founder S42: item 2b native-first); P-4/D-090/FR-47–FR-50; D-066/D-067 (native reader keeps Record-Not-Found for omitted sector IDs — this slice narrows their data rule as D-080 and D-089 did); D-076, D-080 (C-11c on writable images), D-089 (track-0 identification), D-097 (quarantine). JASPP captures omit some standard sectors. When an omitted sector lies inside a file's data, a native load of that file fails with "Disc error 18", while ADFFS presents such sectors as zeros (S42 private evidence). Slice 20 lets the native path read omitted sectors that the disc's **own file system** proves to hold file or directory data as zero-filled sectors, so multi-disc titles such as 68, 69 (and 200) boot natively to their own disc prompts and keep saves in the RW data disc's store. It changes no routing and deletes nothing (the install path stays until later item-2b slices).

**Verified state (`main` `56382d2`).** Effective-sector view `core/jfd_layout.c` ≈ :150–260: captured sectors, then D-089 `identification_mask` (track-side 0, ID-only; data reads RNF), then `creation_mask` slots — created data, or C-11c `formatted_blank` (1024 zero bytes) when `overlay->map_enabled && map_valid && allocation_mask && !probe_mask`. `libretro/arcdroid_libretro.c` `arc_finish_jfd_preparation` (≈ :2559) sets `map_enabled = native && overlay->writable` and calls `arc_jfd_map_prepare` then `arc_jfd_prepare_identification`. C-11c masks (`core/launch_discovery.c` ≈ :818–976) mark any non-free byte (old map) or allocated fragment (new map) and union valid copies — **not** a file-data proof. The D-076 planner (`libretro/jfd_store.c`) runs only for RW candidates; WP/no-RW/legacy images return before creation planning (≈ :413–421); a damaged store can keep committed records visible with `writable=false` (≈ :487–500); a commit failure clears `writable` mid-lifetime (≈ :388). Controllers: `engine/arculator/src/disc_jfd.c` :201–390 (READ ADDRESS/READ ID, data, RNF), `82c711_fdc.c` :638–678 (multi-sector/EOT), `wd1770.c` :147 (single-sector reads only). Discovery's directory reader (≈ :1331–1381) does not check the directory check byte. Existing option precedent: `arcdroid_short_tail` (Slice 15).

**C-1 Read-presentation policy (native path only).** At JFD preparation for a native session, for each image, compute a separate, immutable **file-data presentation plan** (not `map_enabled`, not the D-076 creation masks, never from partially populated D-076 state). A slot qualifies iff all hold:
- (a) **Session class:** the image's overlay is not guest-writable at preparation (WP flag, no RW flag, legacy header, `layout-unsupported`, or `Disk Writes: Off` — which hides saved changes, so the base view is coherent). Images with **any damaged store** are excluded (class `damaged-store`; current reads unchanged; `Disk Writes: Off` hides records as today but does not repair or clear damage, so damaged + Off stays excluded). Class precedence: damaged-store > writable (C-11c) > disk-writes-off > wp-flag > no-flag > legacy-header > layout-unsupported. Writable images keep C-11c exactly as today. The class is frozen at preparation: a later commit failure does not activate the plan mid-lifetime.
- (b) **Geometry:** the image's format is D or E: the nominal 800 KiB interleaved five-sector DD geometry (IDs 0–4, 1024-byte DD sectors). D has one old map (its two checksum-protected halves); E has two independently validated map copies; both use fixed 2048-byte directories (the code distinguishes map format from directory format, `core/launch_discovery.c` ≈ :216–277). Do not require exactly 160 JFD track-table entries (beneficiaries have 166) or a D-map declaration of exactly 3 200 units; only existing track-sides 0–159 are candidates; respect the validated declared logical extent and supported physical bounds; never infer physical capacity from decoded payload length. F, L, quad and other formats get no plan (`reason=format`). The track-side is not quarantined (D-097), and either empty or **regular** (every stored descriptor: unique standard ID 0–4, 1024 bytes, DD, payload-owning, good CRCs, no slow flag, no coincident rotational positions — the D-089 regularity predicate); an explicit descriptor without payload is not an omission.
- (c) **File-system proof over original captured payloads only** (committed replacements, created sectors and synthetic zeros are never input; frozen until re-preparation): parse every complete valid base map copy independently (never assemble F-style zones across copies — not applicable in this scope — and never union eligibility masks); at least one valid copy; where several are valid they must agree on geometry, root and the full reachable-object interpretation used, else no plan (`reason=map-conflict`). Walk the directory tree from the root through **validated live entries only**: format-appropriate structure, start/end sequence agreement, and the directory check byte (with any verified legacy exception documented); an unreadable or invalid root yields no plan; a validated parent proves a child directory's own defined storage extent (its full defined length, including its unused entry area) even if the child sits partly in omitted slots, but a child contributes descendants only if its **original captured** contents validate; never parse synthetic zeros; never follow parent pointers; detect cycles and conflicting aliases by object identity and resolved extent; bound depth, entries, objects, map-resolution work and memory — on exhaustion publish nothing (no order-dependent partial result). Old map (D): object bytes = disc address × 256 for the recorded length, checked against the validated free list, the physical geometry and reserved regions (map, root, boot block). New map (E): resolve the object's fragment ID, sharing offset and successive extents in FileCore order; mark only that object's logical bytes, not the whole fragment or other sharers; reject unsupported sharing/big-directory formats. Reject contradictory allocation, arithmetic overflow, unresolved extents and objects beyond the physical image (no silent truncation). Reserve the actual map regions and the resolved root extent against conflicting object claims; D/E floppies have **no boot block** — do not reserve `0xC00`; a file sharing E's system fragment (ID 2) is judged by its resolved byte extent, not rejected for its fragment ID. Zero-length objects contribute nothing; maps, defect/reserved regions and system-fragment padding never count as file data.
  **Failure scope:** root failure disables the image plan. A child directory whose complete original contents cannot be validated supplies no descendants; its parent-proven 2048-byte extent remains eligible; unsupported directory lengths or formats are never guessed. Map disagreement, contradictory allocation, cycles, conflicting aliases, an invalid object reference in a validated directory (e.g. an address or extent outside the image), arithmetic failure and resource-limit exhaustion **disable the whole image plan** (same rule for every map interpretation). A map copy's validity is judged independently of whether its directory walk succeeds (a structurally valid map whose walk fails still counts and, if it disagrees, blocks the plan); agreement is compared on root, and for every reachable object its type, logical length, sharing offset and ordered physical extents — equal final masks alone do not establish agreement. Named limits (constants, boundary-tested at the limit and one beyond, and traversal-order independent): depth 16, directories 512, objects 8 192, map-resolution steps 65 536. This stricter proof is private to R1′; the shared launch-discovery reader and C-11c are not tightened.
- (d) **Coverage (sector-granular):** a candidate qualifies when its physical sector intersects a validated object's resolved logical data bytes; the entire sector is then presented as zeros, including any leading or trailing bytes outside that object (a FileCore load reads whole sectors, so a missing first or terminal sector fails the load like an interior one). A sector with no such intersection stays ineligible even if allocated — whole slack sectors beyond an object's end and wholly free sectors do **not** qualify (under ADFFS they return errors; S42 evidence). The returned sector must lie within supported physical bounds and must not overlap protected file-system metadata (map regions).
- (e) **Placement:** the slot gets a deterministic base-derived rotational position from the complete standard schedule shared with D-089 (captured sectors never move). Sharing the schedule does not combine eligibility: D-089 computes exactly its existing mask and positions independently of R1′; R1′ never makes additional D-089 IDs appear nor suppresses existing ones when its own proof fails. An unplaceable side gets no R1′ presentation (other sides unaffected).
- (f) **Remembered boot outcomes:** the Slice 14 boot-media digest/stamp (`libretro/arcdroid_libretro.c` ≈ :3900–3987) includes the effective file-data presentation (policy revision and whether the plan is active per image), so an observation established under a different presentation — including every observation from `main`, and either direction of an option change — never suppresses a fresh boot attempt; unchanged policy reuses it. Content identity, CMOS keys and save-store keys stay unchanged.
A qualifying slot reads as 1024 zero bytes with good ID and data CRCs and a visible ID (READ ADDRESS/READ ID) at its planned position. All candidates not newly presented retain their pre-Slice-20 behaviour, including existing C-11c and D-089 exceptions (so free, system, slack, irregular, quarantined and out-of-scope-format omissions of non-writable images keep Record-Not-Found); writes and FORMAT stay refused exactly as today for non-writable images; committed replacement and created-sector data keep precedence wherever they exist; D-076 gate outcomes unchanged (a read exception never makes an image writable); decoded bytes, descriptor ordinals, D-029 identity, JFD store keys and store format unchanged; ADFFS and install sessions untouched (they are not native).
**C-2 Override (FR-50).** New core option `arcdroid_jfd_omitted` "JFD Omitted Sectors": `file-data` (default; C-1) / `strict` (disables only the Slice 20 plan: captured sectors, visible committed records, writable C-11c and D-089 identification keep `main`'s behaviour — it does not mean every omitted slot returns RNF or lacks an ID; media/controller behaviour identical to `main`). **Sampling:** read and validated at content load and explicit reset only; every other preparation (eject/reinsert, disk-control replacement, boot recovery, chooser fallback, install fallback) uses the latched session value, so a frontend option change alone never alters a mounted plan or a later-inserted image until load/reset.
