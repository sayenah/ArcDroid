## Scope
1. **Controller-driven pointer (D-026).** Port 0 default device `ARC_DEVICE_KEYS` (rename its `SET_CONTROLLER_INFO` label to "RetroPad: keys and pointer") additionally drives the Archimedes mouse. Right stick (default) = pointer **velocity**: radial dead zone (default 15 %), monotonic response curve (default quadratic beyond the dead zone, normalised diagonals), speed expressed in mickeys per guest second (default 600, precision modifier R2 = ¼ speed), integrated against elapsed guest time per `retro_run` (not an assumed 20 ms) with fractional remainder. Buttons: R1 = Select, L1 = Adjust, L2 = Menu; they support holds and drags. Existing key map unchanged (d-pad arrows, A Space, B Return, X LShift, Y LCtrl, Start Escape, Select Tab). Core options v2: `arcdroid_pointer_stick` (right / left / disabled, default right), `arcdroid_pointer_speed`, `arcdroid_pointer_deadzone`; options apply on the next `retro_run`. Input descriptors list every default binding (including the analog axes and L2/R2); RetroArch remapping keeps working (digital `RETRO_DEVICE_JOYPAD` reads for L2/R2, no analog-button reads).
2. **Touch gestures (D-027).** In `arcdroid_pointer_mode = relative`, read the pointer stream on port 0 with indexed contacts and `POINTER_COUNT`. A moving contact is pointer motion with no button (fractional motion accumulated, not truncated per sample). A tap (one contact, duration ≤ 250 ms guest time, movement ≤ 1 % of the pointer coordinate range) queues exactly one Select down/up transition pair. Two contacts that both begin within 80 ms guest time of each other and both lift as a tap queue exactly one Menu down/up pair and no Select pair. Select-drag with touch = hold any pad button bound to Select while moving a finger (source merging, Scope 3); no additional drag gesture, no long-press gesture. Rebase (never jump) when the contact count or index changes; cancel recognition on excess movement, extra contacts or offscreen coordinates; reset gesture state on `retro_reset`, content load/unload, device reassignment and option change. Touch never leaves a button held after all contacts lift.
3. **Source-aware input service.** Replace level overwrites with one input service that owns per-source state (keyboard callback, RetroPad keys/buttons, touch gestures, physical mouse ports) and emits **effective** transitions only when the merged logical key/button changes (a source's release never cancels another source's hold). Transitions go into one ordered, bounded FIFO (capacity 256; duplicate downs suppressed; unsupported keys filtered; `KEY_MENU`/`KEY_LWIN` handled explicitly): keyboard-callback order preserved; for sampled changes within one frame, modifiers before dependent keys on press and after on release; mouse-button edges keep their position relative to motion (motion before a click is delivered before it, drag motion before its release). On overflow the service logs once, drops to the current source levels with reserved capacity for releases, and never leaves a key or button stuck. Motion is scheduled so that sustained key traffic cannot starve pointer motion beyond a documented bound (e.g., at most N consecutive discrete events before one motion opportunity under a responsive guest). Stick motion is velocity: it stops being generated on the first sample after release and its outstanding backlog is bounded to one packet; physical-mouse and touch displacement is preserved across packet splitting. Physical-mouse ports remain active alongside touch (no branch suppression); do not double-count RetroArch's touch-as-mouse synthesis.
4. **Consumption-acknowledged delivery (engine boundary exception).** The FIFO advances only when the engine actually consumes: `keyboard_poll` gets **one** ArcDroid hook call at the point where it is eligible to emit (idle KART, keyboard enabled) that applies the next queued transition to `key[]`/button state; nothing advances on skipped polls. Packet encoding, handshake and one-event-per-poll behaviour are unchanged. This is the only permitted engine change; mark it as an ArcDroid modification per `engine/UPSTREAM.md` conventions.
5. **Icon-bar clamp (Defect 2).** Re-test after Scopes 2–4 in this order, with local RISC OS 3.11: cold boot, controller hover before any touch; then corrected touch; then an intentional Select-drag; compare desktop vs F12 BASIC and two screen modes; record delivered KART motion/releases through the test hook where locally observable. If downward packets stop, look at scaling/viewport clipping/motion loss in ArcDroid; if packets continue while guest Y stays at 132, it is guest confinement (Wimp drag box) tied to button semantics. A persistent clamp with correct input is **not** closed by documentation: return it to Fable with the evidence for a Founder decision. No automatic guest-side `OS_Word 21` or memory patch in the shipping core; manual `OS_Word` use is diagnostic evidence only.
6. **E-format (new-map) ADFS recognition.** `arc_media_is_recognised_adfs` (`core/launch.c`) keeps old-map recognition (D-format and older are old-map). Add E-format recognition: bounded disc-record parsing (record at map offset 4 for single-zone media; no hard-disc boot block required), sector/geometry/size consistency, plausible allocation parameters, ZoneCheck and CrossCheck validation. Do not recognise by `Nick`, size or checksum alone. Recognition stays advisory and non-mutating; unrecognised or damaged images keep the existing boot-anyway policy.
7. **Loose ends (low):** stale comment `tests/generate_fixtures.py:239` ("must receive a warning") vs R-36; pin with a test that the faulted-frame path emits no VIDC message if not already pinned; `tools/check-android.sh` / `tools/check-windows.sh` additionally assert that no defined exported symbol exists outside `retro_*` (inspect actual ELF dynamic exports / PE export table, not global symbols); §23 item 10: add a reload/reset test with inputs held and transitions pending.

## Acceptance criteria
- AC-1 Stock RetroPad on port 0, no option changes: right stick moves the pointer in all directions with the dead zone; R2 quarters the speed; R1/L1/L2 produce Select/Adjust/Menu including holds; the descriptor list shows every binding; `arcdroid_pointer_stick=left` works when RetroArch's analog-to-d-pad mode is set to none or right; a RetroArch remap of R1 to another button is honoured.
- AC-2 Full deflection gives a bounded monotonic motion rate in guest time with no ±63 wrap and no lost displacement from mouse/touch sources; stick motion stops being generated at the first sample after release with at most one packet outstanding.
- AC-3 Touch move produces motion with no button; a tap produces exactly one Select down/up delivered to the engine; a two-finger tap produces exactly one Menu down/up and no Select; staggered fingers, jitter at the thresholds, index changes, offscreen loss and contact interruption produce no spurious click, jump or stuck button; overlay on and off both deliver.
- AC-4 Every accepted transition (within capacity) is delivered to the engine in order, including a keyboard down/up inside one `retro_run`, during KART-busy and keyboard-disabled periods, and across 100 randomised key/mouse-button events from multiple sources; overflow and a prolonged guest stall recover to the current levels with no stuck key or button and one logged report.
- AC-5 Odin3 with RISC OS 3.11 (private, local only): using only the built-in controller the pointer reaches and clicks an icon-bar icon, MicroPower Chess 3D is launched from the desktop and a piece moved; repeated with touch hover/tap and with R1-hold touch drag. If the Y = 132 clamp persists with correct input, the PR stays open and the evidence returns to Fable.
- AC-6 A generated E-format image loads without the "not a recognised ADFS image" message; the old-map generated fixture still loads without it; random bytes, a truncated E-format record and a corrupted zone check still log it and boot anyway.
- AC-7 Host `ctest`, Windows load harness, Android/Windows/export guards and CI stay green; no new exported symbol; 100-cycle lifecycle leak-free; reload/reset with held inputs leaves no stuck state.
- AC-8 Scope 7 items closed with tests or documented as intentionally unchanged.
