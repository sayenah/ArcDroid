## Slice 18 work order — CMOS Boot-flag fidelity: a power-on Shift instead of a forced Boot flag (D-101)

**Objective / governing law.** Founder vision D-073, order D-098 (item 2a); P-4/FR-47–FR-50 (general machine behaviour, no per-title data); FR-52–FR-55; D-019/D-031/D-091 (CMOS persistence and its normalisation). On RISC OS 3 a real user boots a floppy with Shift-Break when the machine is configured NoBoot (the PRM's Boot/NoBoot inversion). ArcDroid instead forces the stored Boot flag on every construction, so loaders that read the flag as their own phase marker (save CMOS → `*Configure Boot` → reset → restore) skip their first pass and fail (99: "Handle is either illegal or has been closed"; 185: "Not enough memory in module area"). Slice 18 makes the stored flag faithful and keeps today's unattended power-on auto-boot. It is a prerequisite for Slice 19, which would otherwise move 99/185 to a failing native path.

**Verified state (`main` `eb10158`).** `core/cmos_defaults.c:95–139` `arc_cmos_machine_image`: for RISC OS 3.00/3.10/3.11/3.19 it copies the firmware default or persisted payload, then forces logical byte 5 = 8 and **sets logical byte 16 bit 4** (`output[80] |= 0x10u`, `:123`), plus the launch-owned bytes 11/135 and the checksum; RISC OS 2/Arthur/test are not forced. All four upstream default dumps have the Boot bit clear. `:141` `arc_cmos_normalise_payload` (unplug bytes, bytes 11/135); `:152` `arc_cmos_boot_stamp_payload`. `libretro/arcdroid_libretro.c:1079` `arc_seed_cmos` (record load, D-091 healing `:1099`), `:1125` `arc_persist_cmos`; `:5702` `arc_construct_machine` (engine start `:5751`; input reset `:5782`); `:5064` `arc_poll_inputs` (frontend cleanup `arc_input_reset` `:5111`; observer cancel on any effective key or button `:5233–5238`); `:4518` keyboard callback cancels the observer; `:4569` input reset; `:6476` `retro_reset`. `core/input.c` sources (`ARC_INPUT_SOURCE_*`, `core/arcdroid_core.h:389–396`), `:74` `arc_input_reset`, `:89` `arc_input_clear_source`, `:101` `arc_input_source_key`; `engine/arculator/src/keyboard.c:373–400` (KART). `engine/arcdroid_engine.c:73` `arc_engine_boot_watch_swi` (the SWI hook from `arm.c:2507`, all SWIs). `core/boot_observation.h:10` `ARC_BOOT_OBSERVATION_REVISION 1`. **Probe evidence (private, S41).** A throwaway core that skips the forced flag and holds left Shift from construction: no hold → nothing boots (FDC 0); holds of 20 ms, 60 ms, 160 ms, 0.46 s, 0.96 s and 1.96 s all boot the helper on 3.11; a 20 ms hold also boots on 3.00/3.10/3.19 and on the A3020 (New-IO) and A3010 (ARM250) (no hold on the A3020: no boot); **the chosen hold, released at ≈ 1.0 s, boots the helper title 62 (plays) and the self-booting 185 (reaches its game) on 3.00, 3.10, 3.11, 3.19 (A3000) and 3.11 on the A3020 and A3010**; the kernel's boot action `OS_FSControl 15` arrives 11.39 s (3.00), 7.80 s (3.10), 7.82 s (3.11), 8.03 s (3.19), 7.0–7.5 s (A3020/A3010, 3.11) after construction, so a release trigger at ≤ 1 s precedes the boot action by more than 6 s in every tested configuration (this does not by itself prove guest-visible key-up timing for the final FIFO implementation — AC-3). 99 and 185 reach their games natively (no package) on first launch and on a second launch with the same saved state (3.11; 185 also 3.00; 99 also 3.10; 99 on 3.00 stops at "System variable 'Resources$Path' not found" — that loader's own RISC OS 3.00 limitation, not a regression). A harness-level Shift cancelled the Slice 14 observer (47/48/125/197 lost their recovery); the in-core version restores it.

**C-1 No forced Boot.** `arc_cmos_machine_image` stops setting logical byte 16 bit 4 for RISC OS 3.00/3.10/3.11/3.19. Byte 5, the launch-owned bytes 11/135, IDE attachment and the checksum rule are unchanged. Fresh defaults keep the firmware dump's own (clear) value.

**C-2 The Boot bit is launch-owned in persisted records.** Logical byte 16 bit 4 joins the launch-owned normalisation for the four RISC OS 3 classes: cleared in the host-side payload on record load and on every persistence (periodic, teardown, reset, recovery), never in the running machine — live guest CMOS stays authoritative (a loader's `*Configure Boot` + its own reset works); no runtime write suppression (unlike D-091). Other bits of byte 16 and all other bytes are untouched; record format and key unchanged. Existing records carrying ArcDroid's forced bit heal on load. Accepted restriction (D-101): a loader that relied on a *persisted* Boot phase marker across a process restart re-runs its first pass (C-3 still boots it); no library title is known to need that.

**C-3 Power-on Shift.** At every machine construction on those four classes — initial load, frontend reset/reload, chooser confirmation, Slice 14 direct and cached recovery, ADFFS and install sessions — whose constructed starting CMOS has the Boot bit clear, a dedicated internal input source holds **left Shift from power-on** and **releases it at the earlier** of (a) 1 000 000 µs of emulated time after construction and (b) the guest's first `OS_FSControl 15` (SWI &29 or &20029 with R0 = 15). Key-down and key-up then travel the normal keyboard path (input FIFO → KART), whose delivery waits for an enabled, idle controller; the guest-visible key-up therefore follows the release trigger by the delivery delay, which the tests measure. The boot-action trigger is detected at the engine SWI hook **independently of the Slice 14 observer** (today `arc_engine_boot_watch_swi` returns unless the observer is armed; helper, ADFFS and install sessions do not arm it). It reproduces today's unattended power-on auto-boot while the stored flag stays faithful. Ownership: a dedicated internal input source composed with the frontend sources — frontend cleanup (`arc_input_reset` in `arc_poll_inputs`, construction, chooser gates, `retro_reset`) neither clears it nor is defeated by it; releasing it never releases a user-held Shift and vice versa; it does **not** count as frontend input for the Slice 14 observer, while genuine frontend input — including a user's own Shift — still cancels observation; it is armed only by core constructions, never by a guest-initiated reset; teardown discards any pending transition so none leaks into a later machine. Sessions whose constructed CMOS has Boot set (not reachable after C-2, but keep the branch) get no Shift. **User-visible change (accepted, release note):** a user holding Shift at power-on used to suppress auto-boot; now the internal Shift composes with it and the boot happens (RetroArch offers no power-on Shift workflow; `Launch` options control launching).

**C-4 Boot observation.** `ARC_BOOT_OBSERVATION_REVISION` 1 → 2: revision-1 observations are discarded once; the stamp still covers the constructed starting CMOS after normalisation (pre-execution state, never post-loader CMOS).

**C-5 Diagnostics.** One INFO line per construction on the four classes: `Power-on: boot-flag=clear shift=held` (or `boot-flag=set shift=none`), and one at release: `Power-on: shift released at=<µs> reason=timer|boot-action`; one INFO line when a loaded record's Boot bit was cleared: `CMOS: cleared launch-owned boot flag`. No frontend notice. Release note `docs/release-notes-slice18.md` (behaviour, the healed records, the Shift change, observation revision).

**C-6 Non-goals.** JFD routing and the native-route table (Slice 19); RISC OS 2/Arthur/test OS behaviour; byte 5; reviving SAVE_RAM (stays absent, D-059); ADFFS package or install-recipe changes; any per-title data or content detection; any change to what boots at power-on.
