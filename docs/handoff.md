## QA adjudication and remediation order (2026-09-15)
Sources: Fable device acceptance (AC-9, Odin3, this session) and the Opus QA report at `c9d3bb9` (attached to PR #28). Every item below is validated remediation; anything not listed was classified as accepted-as-designed, out of scope, or incorrect, and is recorded in the adjudication notes.

Defects (fix):
- R-44 **Multi-member gzip JFD rejected (Fable device finding; handoff constraint error).** ADFFS writes a JFD as two concatenated gzip members (member 1 = the header, member 2 = tables and data; the Founder's JASPP image decodes to 316 + 521 200 bytes = the declared size; gzip OS byte 13 = Acorn RISCOS). RFC 1952 §2.2: "A gzip file consists of a series of members… one after another… with no additional information before, between, or after them." Replace Scope 5's "one member only" with: decode consecutive members until the input is exhausted, verifying each member's header, CRC32 and ISIZE, concatenating outputs under the existing 8 MiB decoded cap and the no-progress rule; reject any non-gzip bytes after a complete member and any member that overruns the cap. Add a generated two-member fixture that mirrors ADFS layout (header member + body member) to the JFD family and the CI packaging, a `core_tests` case for it (accepted; single-member, three-member, member truncated mid-stream, trailing garbage after members rejected), and run it through the harness JFD load. With the members decoded to a plain `JFDI` file the same JASPP image already loads (166 track-sides, 504 sectors) and RISC OS shows its Filer on the device, so no reader change is needed for it.
- R-45 **Spurious not-found after an aborted or superseded empty-drive command (Opus H-1, regression of Scope 8).** `disc.c` now decrements `disc_notfound` unconditionally, but Force Interrupt and a new Type I command do not cancel it (`disc_stop` is a no-op with no reader), so `notfound` fires ~320 ms later, clobbering status and raising INTRQ (Opus reproduced: `0x84` → `0x10` with an IRQ 400 ms after Force Interrupt). Cancel `disc_notfound` on Force Interrupt, on every new command, and in `disc_stop` regardless of a mounted reader; add the abort-then-idle and Restore-then-idle cases through the real controller (no completion for one further second).
- R-46 **`retro_reset` with an empty image list unloads the session (Opus M-5).** After `replace_image_index(i, NULL)` removes every entry, reset builds the launch plan from a zeroed entry, fails "launch plan inputs are invalid" and tears down. Reset with no populated entry must restart the machine with no disc, keeping count 0, selection none, tray state, options and the frozen identity; add the remove-all → close → reset harness case.
- R-47 **Windows root-relative `/dir/x.adf` accepted and mis-resolved (Opus M-6).** On Windows hosts reject entries beginning with `/` as root-relative, like `\`; add the vector.
- R-48 **Write Sector asserts DRQ and delivers a data byte before a write-protect or empty-drive completion (Opus L-1, introduced by the `wd1770.c` reorder).** Keep `index_count`/`rnf_detection` armed before the reader hand-off, but assert DRQ only after the hand-off and only while the command is still busy; assert `drq=0 bytes=0` for Write Sector and Write Track on write-protected JFD media and on an empty drive.

## Scope
1. **Playlists** (`core/playlist.c`, pure). `.m3u` content or any text beginning (after an optional BOM) with `#EXTM3U`: UTF-8, LF/CRLF, blank and `#` comment lines ignored, optional `#EXTINF:...,<label>` naming the next entry; limits 32 entries, 128 KiB file, 4 095 bytes per resolved path, 127 bytes per label (longer labels rejected, not truncated); NULs, nested playlists, unsupported or overlong entries and empty playlists rejected; order and duplicates preserved (duplicates share a shadow by digest). Path grammar: an entry is absolute when it is a supported serialised VFS path (`saf://`), a POSIX path starting `/` on non-Windows hosts, or on Windows a drive-rooted `X:\`/`X:/` path or a UNC `\\server\share` path; drive-relative `X:foo` and root-relative `\foo` are rejected; everything else is joined to the playlist's directory using the playlist path's own separator, with `.` and `..` segments rejected and no other normalisation (SAF identifiers stay opaque; no CWD, shell or environment expansion). Every entry is read, classified, validated and staged before the machine starts; the first failure aborts the load with one message naming the line (or the file for oversize/empty playlists) and the reason; temporary files and persistent copies created by the failed preparation are removed, pre-existing shadows retained. The user's m3u is never rewritten.
2. **Disk-control state machine** (libretro ext contract): count = list length including an unfilled append reservation, 0 after unload; "none" is represented internally and reported as count; `set_image_index` requires an open tray, `< count` selects a populated entry, selecting an unfilled reservation returns false and preserves selection, `≥ count` selects none; eject is idempotent, stops the mounted operation, detaches, preserves selection; close mounts the selected populated entry or closes empty, and a mount failure leaves the tray open and clears the engine's saved mount state (reset must not resurrect the old path); `add_image_index` appends one reservation (cap 32); `replace_image_index(i, info)` requires an open tray and prepares the image fully before committing (failure keeps the existing entry; a failed fill of a freshly added trailing reservation rolls that reservation back); `replace(i, NULL)` removes and compacts (selection decremented when an earlier entry goes; removing the selected entry selects none); path/label return false for invalid index, none, or an unfilled reservation, and check buffer capacity. Labels: `#EXTINF` label, else JFD disc title (sanitised printable ASCII, ≤ 127 bytes), else file stem. `get_image_path` = resolved source path, never a staged path. The two-slot stub is removed.
3. **Initial image and reset.** `set_initial_image(i, path)` copies a bounded pending request (NULL/overlong input rejected without partial state); the next load consumes it exactly once after the list exists and honours it only when `i` names a populated entry whose resolved source path equals `path`, else index 0 (never none); pending state is cleared after success, failed load, unload and deinit. `retro_reset` is a retained-session machine restart: it persists CMOS, re-reads core options and defines each option as live / reset-time / next-load, re-selects firmware and write mode coherently for the adapter and the mounted reader, restarts the engine, and preserves the media list, selection, tray state, shadows, frozen identity, adapter timing/input reset semantics, audio reset and A/V notification coalescing exactly as today; failure of firmware selection or staging during reset is reported and leaves the session unloaded rather than half-restarted. Unload stops media before freeing buffers and retains persistent shadows.
4. **Identity (D-019, D-029).** Standalone raw image: SHA-1 of the supplied bytes (unchanged). Playlist: `SHA1("arcdroid-playlist-v1" || u32 count || ordered 20-byte entry digests)`, frozen at load until unload; selection, append, replace, removal and reset never rekey. JFD: SHA-1 of the decoded `JFDI` bytes. Short image: SHA-1 of the supplied bytes before padding. Shadows stay keyed by each image's own digest.
5. **Decompression** (D-010). `third_party/zlib/`: pinned zlib 1.3.2 in-memory inflate subset (`adler32.c crc32.c crc32.h inffast.c inffast.h inffixed.h inflate.c inflate.h inftrees.c inftrees.h zconf.h zlib.h zutil.c zutil.h`; no `gz*`, no deflate), compiled statically with hidden visibility into the core on host, MinGW-UCRT and NDK with `NO_GZIP`/`Z_SOLO`-style definitions so `gzguts.h` is never included; Android stops linking system `libz` (the guard allowlist may keep `libz.so`). Exact upstream tarball/commit digest, file allowlist, compile definitions and the unmodified licence are recorded in `THIRD_PARTY_NOTICES.md`. Gzip handling: `inflateInit2(15+16)`; consecutive members decoded until the input is exhausted (RFC 1952 §2.2; ADFFS writes header and body as separate members), each with `Z_STREAM_END`, CRC32 and ISIZE verified, outputs concatenated under the 8 MiB cap enforced independently of trailer claims, no-progress loops rejected, ordinary header variations (name, comment, timestamp, OS byte) accepted, non-gzip trailing bytes rejected; ISIZE is never used as an allocation request (R-44). Guard: `tools/check-shipping-io.sh` scans every new compiled source/header, adds a `gz[a-z]*(`, `open(`, `_wfopen(`, `CreateFile` family pattern with self-test, carries narrowly enumerated line-level exceptions for zlib's unused `F_OPEN` macro definitions only, and additionally checks (via `nm`/`llvm-nm` on the compiled zlib objects) that they reference no file-I/O symbol.
6. **JFD parser** (`core/jfd.c`, pure over a byte buffer, explicit little-endian loads, no unaligned struct casts, no I/O, no static per-drive arrays). Implementation limits (not format maxima): 8 MiB compressed, 8 MiB decoded, ≤ 166 track-side entries, ≤ 256 descriptors per track-side including duplicates, sizes 128–1024 (codes 0–3; other nibble values rejected), title 256 bytes bounded (a full 256-byte title without terminator is accepted and truncated to 255 for display). Validation: `JFDI`; header +8 equals the decoded length; any min-ADFFS-version value accepted (ArcDroid does not run ADFFS); legacy header when `offset_track` is in [304, 316), extended fields parsed only when `offset_track ≥ 316`; `offset_track < offset_sector ≤ offset_data ≤ decoded_len − obey_length`, all 4-aligned, `(offset_sector − offset_track) % 4 == 0`, track count in [2, 166]; each track entry either `0xffffffff` or a 4-aligned offset with `offset_sector + entry < offset_data`; each sector list terminated by a 4-byte `0xffffffff` within `[offset_sector, offset_data)` and within the descriptor cap (shared lists allowed); each data offset either `0xffffffff` or `offset_data + off + (128 << s) ≤ decoded_len − obey_length` (shared payload offsets allowed); `tt ≤ 200` or `0xff`; density ∈ {1, 2} (4/8 → image rejected, reason "quad/octal density unsupported"); unknown flag bits and reserved bytes ignored and logged once. Rejected with a named reason: any non-zero delta table offset, any DiscOp 3 entry (B bit 0), a track-side mixing timed and untimed entries, untimed duplicate IDs on one track-side, a synthesised track schedule exceeding one revolution. An uncompressed `JFDI` file is accepted through the same parser. Output: immutable track/sector descriptors owned by the adapter's media session; freed on eject/unload after the reader is stopped. Title, sequence, flags, fps and obey length are logged once (Slice 2b inputs) and not acted on.
7. **JFD engine reader** (`engine/arculator/src/disc_jfd.c`, ArcDroid-authored rewrite under the ArcDroid notice, GPL-2.0-only, upstream credited; receives descriptors via `arc_engine_media_insert`, never re-parses in the engine). Reference schedule and results:
   - Revolution R = 200 000 µs of guest time advanced by the disc poll quantum; the index pulse fires when the phase wraps; phase persists across seeks while the motor runs and is reset to 0 on insert, eject, machine reset and motor start.
   - Explicit times: t = tt × 1000 µs, 200 000 ≡ 0. Untimed track-sides: t_k = Σ_{j<k} (112 + (128 << s_j)) × cadence in table order, cadence 32 µs/byte for density 2 and 64 µs/byte for density 1. Equal times: table order.
   - A sector is available in the first poll after command start whose phase interval [old, new) contains t (wrap handled); a sector exactly at the current phase is therefore available on the first poll.
   - Matching: physical side, controller density (0 ↔ 1, 1 ↔ 2), ID `nn`; Read Address returns physical track, side, `nn`, `s` and computed CRC bytes through the six-byte `data` path. Duplicates are selected by next rotational occurrence, never collapsed.
   - Results: ID-CRC entry → header CRC completion (both flags set → ID-CRC precedence, no data); data-CRC entry with payload → payload bytes then data-CRC completion (exactly one completion, no `finishread` success afterwards); entry without payload → ID-only: Read Address succeeds, sector read/write → not-found after the controller's five index pulses; blank track → index pulses only, not-found within five revolutions; write/format → write-protect completion in every `arcdroid_disk_writes` mode (logged as ignored); slow-sector flag has no effect (all transfers already run at floppy speed); transfer cadence one byte per poll quantum as `disc_adf.c`.
   - Structure: every reader completion (including write-protect and not-found) is delivered from `poll`, never synchronously from `readsector/writesector/readaddress/format`; each `poll` does bounded work (capped descriptor search + one transfer step); every terminal result returns the reader to idle with no later callback; `stop` cancels any pending operation; reader command/rotation state is reset on init, load, close and teardown; no VFS read, allocation or decompression in the poll path.
8. **Engine boundary fixes** (bounded changes to `disc.c`, `wd1770.c/.h`, `disc_adf.c/.h`): empty-drive read/write/address/format complete not-found without a mounted reader; every terminal controller callback (`notfound`, `datacrcerror`, `headercrcerror`, `writeprotect`, overrun) and Force Interrupt clear `rnf_detection` and cancel the command timer, with explicit final Busy/DRQ/IRQ state; reader error completions are never lost to the controller's post-handoff DRQ/`rnf_detection` setup; `disc_adf.c` resets all static command/rotation state on init; eject during a command resolves pending controller timers/DRQ/IRQ; ADF→JFD→ADF swaps with pending reads and writes leave no stale operation. The prepared media type and geometry are passed through the engine boundary (`arc_engine_media_insert` gains kind/geometry/descriptor arguments); the engine never re-detects media from staged bytes.
9. **Short raw images.** `arc_media_inspect` takes bytes and returns format, geometry, declared length, available length, recognition strength and required padding. Exact-size raw images remain launchable with the ADFS advisory (failed FileCore recognition on exact-size raw media is advisory; a malformed strong container signature — `JFDI`, gzip — is a rejection). A short image is accepted only when a validated descriptor declares a supported geometry and the missing tail is sector-aligned and ≤ one physical cylinder:
   | Geometry | Descriptor evidence (all required) | Max missing tail |
   |---|---|---:|
   | 800K E (5 × 1024 × 2 × 80) | disc record at +4: log2secsize 10, secspertrack 5, heads 2, density 2, disc size (+16) = 819 200; ZoneCheck and CrossCheck valid (existing `arc_new_map_e_format` with the file-length comparison replaced by the declared size) | 10 240 |
   | 640K L (16 × 256 × 2 × 80) | old map: Check0/Check1 valid (254→0 rule), `OldSize` (bytes 252–254 LE) = 2 560, `FreeEnd` (byte 509) ≤ 246 and a multiple of 3 | 8 192 |
   | 320K (16 × 256 × 1 × 80) | as 640K with `OldSize` = 1 280 | 4 096 |
   | 800K D (old map, 5 × 1024 × 2 × 80) | as 640K with `OldSize` = 3 200 | 10 240 |
   Anything else (non-aligned, larger shortfall, over-long, unrecognised) is rejected naming the nearest geometry and the shortfall/overshoot. Write-mode policy: `shadow` → full-size zero-padded shadow initialised once, guest writes retained across resets, swaps and reloads; `off` → padded read-only staged copy; `original` → rejected with an actionable message naming shadow/off (the original is never grown). One WARN line and one OSD message state the missing byte count. Old-map checksum direction fixed; an independent checksum vector (taken from a RISC OS-mounted disc, not from the implementation) added to `core_tests`.
10. **Staging.** Immutable decoded-JFDI staging, padded raw initialisation and mutable raw shadows are distinguished. Immutable copies are reused when length and SHA-1 both match, otherwise recreated; new files are written to a temporary sibling, flushed, closed (errors propagated) and published by VFS `rename` to an absent destination (`arc_io` gains `rename`/`remove`; write, flush, close and rename failures propagate; owned temporaries cleaned up). A writable shadow with a structural fault (wrong length, failed read) is reported, never silently overwritten or removed; FileCore checksums are not required of a writable shadow. Raw writes stay eager. On every insert the staged JFDI is re-read, digest-checked and re-parsed; only one decoded JFD buffer (plus one compressed input during preparation) is live. A native, writable save directory is required; a `saf://` save directory fails the load with an actionable message. Total staged logical media ≤ 256 MiB per load (duplicates counted once).
11. **Detection and extensions.** Admission order for new source bytes: `JFDI`, gzip-wrapped `JFDI`, validated FileCore descriptor, exact-size raw fallback; a structured signature that fails validation is rejected, never falls through to raw. The admitted format is retained for the image's shadow (guest-written bytes never change the selected reader). Playlists by extension or `#EXTM3U`. `valid_extensions` and `.info` = `adf|adl|jfd|m3u`. Archived playlists unsupported.
12. **Media-exerciser ROM** (project-authored, generated by `tests/generate_fixtures.py`, fingerprinted as a second `ARC_OS_TEST` entry in `core/firmware_table.c`): runs a fixed WD1772 script with bounded waits per command — seek, read sectors on two tracks and both sides, one Read Address, one write attempt — records each command's final status byte and a checksum of transferred bytes into a results table, paints the table as a machine-decodable region of the frame (each result byte as a row band) plus a payload-derived pattern, then loops re-reading track 0 sector 0 every ≈ 1 s of guest time and repainting so swaps become visible. The existing test ROM and its regression tests are retained unchanged.
