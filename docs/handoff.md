## Work order — Slice 5b: folder disc sets (D-041; Astra challenge 2026-09-20, all four findings incorporated)
**Objective (PRD FR-8, FR-4, FR-5; Founder order 2026-09-19):** a multi-disc game stored without a playlist gets working libretro disk control with no user setup. **Verified state:** `arc_prepare_media_list` (`libretro/arcdroid_libretro.c`) loads one image or an `.m3u` (≤ 32 entries, 256 MiB logical bound, every entry inspected, digested and staged at load; any failing playlist entry fails the load; `arc_cleanup_failed_preparation` clears the whole list including index 0). `libretro/arc_io.c` already lists directories through the frontend VFS. The initial index restored by `set_initial_image` selects the image that boots and that launch discovery inspects. Library evidence (private; shapes only): 65 folders, 171 images, 2–10 per folder, `.jfd` and `.adf`, one folder mixing both; siblings carry a catalogue number ending `…02`, `…03` or `(Disk 2)` … `(Disk 10)`; some siblings are images the reader rejects.

**Behaviour**
- **AC-1 Trigger (structural only).** Content that is an image (not a playlist), given as a native filesystem path, whose parent directory's name equals the file's own name (byte-exact; ASCII case-insensitive on Windows hosts) is a *folder set*. Nothing else triggers it: no name vocabulary (D-039), no sibling guessing for loose images, no core option. A path containing `://` (SAF or any URI form) never triggers discovery and loads exactly as today.
- **AC-2 Membership.** Regular files directly in that directory (no recursion) with extension `adf`, `adl` or `jfd` (ASCII case-insensitive), excluding names that begin with `.` and excluding the selected file itself under the AC-1 comparison rule (a differently cased spelling on Windows must not add it twice). `.m3u` files there are ignored. Original path spelling is preserved for VFS calls and disk-control callbacks.
- **AC-3 Order.** The selected file is index 0. Siblings follow in natural order of the file name: runs of ASCII digits compare numerically, other bytes ASCII-case-insensitively, ties by plain byte order. The result does not depend on `readdir` order or host.
- **AC-4 Failure policy.** The selected image loads, fails and reports exactly as it does today. Any failure preparing a sibling (unreadable, rejected by the reader, shadow fault, directory creation, allocation, publish) omits that sibling with a logged reason and one summarising user message for the load; it never fails the load and never disturbs index 0, its staged file, or an existing writable shadow (including a staging path shared through a duplicate digest). If the directory cannot be opened, more than 31 siblings qualify, or the 256 MiB bound would be exceeded, the selected image loads alone with one message. A listing that ends early cannot be detected (VFS `readdir`); do not claim a warning for it.
- **AC-5 Path-length guard.** If the parent directory path is longer than 1021 bytes the core does not call VFS `opendir` and loads the selected image alone with one message (RetroArch 1.22.2's Windows `retro_vfs_opendir_impl` overruns a 1024-byte buffer). Applies on every host. The boundary test must not call the frontend with an over-long path.
- **AC-6 Identity (D-041).** Content identity is the selected image's existing D-029 identity (raw bytes, decoded `JFDI` bytes, pre-padding bytes), never a playlist-style digest; it does not change when siblings are added, removed or skipped. Explicit `.m3u` behaviour and identity are unchanged.
- **AC-7 Disk control.** Count, labels (existing rules: JFD title, else file stem), `get_image_path`, eject/select/insert, replace/append/remove and `set_initial_image` work on a folder set exactly as on a playlist. The existing restore contract is kept: a remembered index whose path still matches boots that image; a remembered index whose sibling was removed, renamed or is now omitted falls back to index 0 without selecting a different path.

**Evidence required (deterministic; generated fixtures with invented names only)**
- **AC-8** The trigger, membership filter and ordering are a pure `core/` function with host unit tests: match and mismatch, both separators, Windows case rule and selected-file exclusion, 10-member natural order, dot-file exclusion, mixed extensions, 31/32 siblings, the 1021/1022-byte boundary, `://` paths.
- **AC-9** Host harness on generated fixture folders: count, labels and order; a guest-observed eject → index → insert exchange reaching a sibling's payload; omission of a rejected sibling and of a sibling whose publish is fault-injected, with index 0 and a pre-existing writable shadow intact; identity equal to the standalone digest with and without siblings; load → swap → unload → reload with `set_initial_image` for a present, a removed and a renamed sibling; an unlistable directory; existing single-image and playlist tests unchanged and passing.
- **AC-10** The Windows RetroArch CI job loads a fixture folder set and observes disc 1, then a sibling after eject/next/insert, following the existing playlist media check. `tools/check-android.sh`, export, shipping-I/O and asset guards pass. CI green.
- **AC-11 (Fable, not Sol)** Odin3, core built from the PR head: for all 65 folders the core's own log shows VFS enumeration of the SD-card directory and the prepared count (files present minus omitted, reasons logged); a guest-observed swap on removable storage for at least three sets including the 10-disc and the mixed-extension set; swap → quit → relaunch on one set; zero regressions on a sample of single-image titles. Words and counts only.

**Non-goals:** automatic disc swapping, a boot-always-from-disc-1 rule (Founder decision 3), playlist writing, lazy staging or staging clean-up, SAF/`content://` discovery, the chooser (5c), media-format or protection work, the Follow-up Lows.
