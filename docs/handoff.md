**C-1 Classification.** Whole-image rejection is unchanged for structural faults and undefined encodings: gzip/size/signature/header/delta/offset/table faults, track entries outside the sector table, truncated or unterminated lists, the 256-descriptor cap, the obey boundary, density codes other than 1, 2, 4, 8, timed values 201–254 (200 → phase 0 and 255 → untimed as today), payloads outside the data table, and allocation failure. A track-side is **quarantined** (the image is accepted) when any descriptor on it has: size code > 3; octal density (8); the DiscOp 3 whole-track flag; a timing mode different from the side's first descriptor; an untimed (ID, density) repeating an earlier descriptor of the side; or when its untimed synthesised schedule (the existing `(112 + size) × cadence` rule) exceeds one revolution. Quarantine covers **every** descriptor on the side, including those parsed before the fault. Parsing continues after a quarantine reason: every later descriptor of the side and of the image is still structurally validated (a structural fault after a quarantine still rejects the image). The first reason per side is recorded. Descriptors on a quarantined side keep their ordinals and are retained for range accounting.

**C-2 Lossless payload extents.** Every payload-owning descriptor, including quarantined ones with size codes up to 15, has a lossless, validated payload extent (offset and length computed without narrowing). Both write-eligibility implementations (`core/jfd.h` and `libretro/jfd_store.c`) use those extents for alias checks, so a quarantined payload overlapping a supported descriptor makes that descriptor ineligible. Only supported, eligible sizes reach snapshot serialisation; the store snapshot format is unchanged. Widening the size field or keeping separate source extents is Sol's choice; narrowing unsupported sizes into the existing field and using it for alias checks is not acceptable.

**C-3 Presentation and consumers.** The quarantined state is explicit (not "zero descriptors") and carried with the parsed image. On either controller a quarantined side presents nothing: no IDs to WD1772 READ ADDRESS / 82C711 READ ID, READ SECTOR ends Record-Not-Found through the existing index-pulse paths (five indexes WD1772, two 82C711), WRITE SECTOR returns write-protect on a protected image and otherwise not-found with nothing committed, FORMAT stays refused. Every other side keeps its bytes, ordinals, timing, density and CRC behaviour. Consumers: the effective-sector view exposes no captured, created, prospective or identification sector on a quarantined side; a quarantined track-side 0 disqualifies D-089 presentation; D-080 produces no blanks, probe marks or creation eligibility there; discovery and map preparation read through the same view (no salvaging of hidden payloads); `arc_media_inspect` and install validation succeed on the structurally valid image (install validation keeps its exact decoded-size/SHA-1 comparison). **D-076 gate:** a quarantined side within track-sides 0–159 stays **non-empty for the majority denominator**, contributes zero compatible/full sides and no writable standard slots; **any** free-space intersection with its standard 5 120-byte coordinate interval, or an unavailable base free-space proof, fails the write-layout gate; failure write-protects the whole image before any write while read preparation still succeeds (existing `jfd_store.c:429–435` behaviour); sides 160–165 stay unavailable and uncreatable, do not enter P-DD5 coordinates or the majority, and their payload ranges still count for alias checks. The existing D-076 map-proof policy is kept (not D-089's).

**C-4 Density, routing, identity.** `high_density` = at least one density-4 descriptor on a non-quarantined side, regardless of CRC flags or payload presence, at initial load, reset and insertion; the same classification feeds `arc_machine_accepts_media`. Routing, zip ordering (D-056 tiers and fallback), reset/swap/reload are unchanged: a quarantined image is a successful preparation. ADFFS always receives the original bytes. Decoded bytes and D-029 identity are unchanged (idx 81's identity now follows its real disc 1 — expected, no migration). Recorded limitation: an ADFFS-routed image whose only quad sector is quarantined resolves to the A3000; the explicit machine option is the recovery.

**C-5 Diagnostics.** One WARN line per quarantined image at preparation, qualified as native-model, e.g. `JFD native quarantine: image=N sides=K first=<track-side>:<reason> [more=M]` (bounded; no per-command logging); nothing for images without quarantine; no frontend notice (the image boots; FR-54). Existing launch-failure and write-protection notices are unchanged. Release note `docs/release-notes-slice16.md` (behaviour, limits: large sectors and overfull schedules are hidden, not modelled).

**C-6 Non-goals.** Modelling sectors larger than 1 024 bytes or re-timing overfull schedules; slow-sector timing; changing D-056; ADFFS behaviour; any per-title data; other broken-launch classes.
