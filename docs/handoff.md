## Slice 13 work order — session-scoped ROM-module unplugging on RISC OS 3 (broken-launch class G6)
**Objective.** A 1991-era loader shared by idx 32 and 38 writes a RISC OS 2-numbered ROM-module unplug mask into CMOS bytes 173–180, sets its own flags in the user bytes and soft-resets through the reset vector; RISC OS 3.x reads those bits with its own module numbering, unplugs FileCore/ADFS/BASIC-class modules and stops at `RISC OS 4096K / Supervisor / *` without touching the floppy. ArcDroid then persists the poisoned CMOS per content, so every relaunch is dead (FDC commands 0). Fix the class generically (PRD P-4, D-090): on RISC OS 3 firmware ArcDroid's machine treats ROM-module unplugging as **session-scoped** — guest writes to the RISC OS 3 ROM-module unplug bytes are acknowledged but never stored by the CMOS device and never persisted; every boot starts with the RISC OS 3 ROM-module unplug fields clear. No per-title data; no option; no notice.

**Verified state (S37, `main` `cbd99d1`).** `engine/arculator/src/cmos.c:319` stores every guest I²C write at `cmos.ram[addr]` (byte protocol `cmos_write` `:243`; bus `i2c_change` `:346`, driven from `ioc.c:72`); reads at `:108`/`:266`. `core/cmos_defaults.c:94` `arc_cmos_normalise_payload(payload, io)` is the D-031 normalisation (bytes 11/135) applied by `arc_sync_cmos`/`arc_seed_cmos` (`libretro/arcdroid_libretro.c:1016`/`:1031`); `arc_cmos_machine_image` (`:47`) builds the boot image and recomputes the RISC OS checksum (logical 239 = raw 0x3F; `arc_cmos_machine_attach_ide` `:104` recomputes it again on install sessions); `arc_engine_start(..., cmos, ...)` (`engine/arcdroid_engine.h:36`), `arc_engine_reset` (`engine/arcdroid_engine.c:600`) recreates the machine from the live image; `retro_reset` (`libretro/arcdroid_libretro.c:5839`) persists, re-seeds from the file and reconstructs (`arc_construct_machine` `:5273`). Persisted record: `ARCCMOS2` per {machine, OS class, memory, content} (D-019/D-029; `core/persistence.c`); no SAVE_RAM (D-059 R-1). Default images hold zeros in every unplug byte. Test hook `arc_engine_test_cmos_write` (`:152`) bypasses the bus. Baseline (host, RISC OS 3.11): idx 38 fresh → `Supervisor` (FDC 21/7 then none); relaunch on its record → FDC 0/0; idx 32 native → same.

**Scope.**
C-1 **Device rule (RISC OS 3 sessions).** (a) The **guest-locked set** is a core-owned function of the session's OS class in logical CMOS numbers: RISC OS 3.00/3.10/3.11/3.19 and the ArcDroid test OS → {6, 7, 18, 19, 173, 174, 175, 176, 217, 218, 219}; RISC OS 2.00/2.01, Arthur 0.30/1.20 → empty. Logical→raw mapping in one place (raw = n + 0x40, minus 240 past 255; payload offset = raw − 16). (b) The adapter passes the set (a 256-bit raw mask) to the engine as an `arc_engine_start` parameter; the engine installs it after `arc_engine_start`'s initial stop and before construction, keeps it across `arc_engine_reset`, and clears it on `arc_engine_stop` and on a failed start. In `cmos_write`'s data phase a write to a locked raw address is acknowledged and advances the address as today but leaves `cmos.ram` unchanged; reads, sequential transfers, the RTC (raw 0x00–0x0F) and every unlocked byte are unchanged. The upstream file gets one small marked hook/mask check, no OS knowledge (`engine/UPSTREAM.md` notice updated). (c) **Checksum.** Logical 239 stays guest-maintained at run time (RISC OS adjusts it incrementally, so a dropped write leaves it drifted until the next construction); `arc_cmos_machine_image` and `arc_cmos_machine_attach_ide` keep recomputing it as today. No device-side checksum logic.
C-2 **Persistence and machine image.** `arc_cmos_normalise_payload` gains the OS class and clears the locked bytes in every persisted payload — at seed (healing records poisoned before this rule, without deleting or rekeying them; `arc_cmos_last_written` keeps the original so the healed record is written through on the next persist), at every sync, in `retro_reset`'s re-seed — in addition to D-031's fields; `arc_cmos_machine_image` builds from the normalised payload so the image carries zeros there; on install sessions the order stays normalise → launch fields → IDE attach → checksum. A raw hook write to a locked byte never reaches the persisted record. Record format, identity, path and keying unchanged.
C-3 **In-session semantics (documented deviation, P-7).** `*Unplug X` still kills the running module (RISC OS does that before writing the bit) but the module returns at the next reset or launch; `*RMReInit` behaves as today; read-back reports the module plugged immediately. No frontend notice.
C-4 **Diagnostics.** INFO, once per content session on the first locked write: `CMOS: guest write to unplug byte <logical> (raw <hex>) ignored: attempted <hex> retained <hex> (module unplugging is session-scoped on <OS class>)`; bounded counters (locked attempts, attempts that would have changed storage) reported once at unload in an existing summary line; INFO at seed when a record had non-zero locked bytes: `CMOS: cleared <n> unplug byte(s) from the persisted record`; the DEBUG `CMOS write` trace keeps logging attempted writes. No per-write INFO, no title text; `retro_reset` does not repeat the first-occurrence line.
C-5 **Tests** (project-authored, invented content). Unit: locked-set membership for every OS enum over all 256 raw addresses (RTC and 181–184, 30–53, 9, 20–21, 177–180 excluded), mapping/wrap, normalisation clearing on a poisoned payload with everything else preserved, machine image zeros, checksum formula. Device (engine test executable in the `jfd_controller_tests` style, compiling `cmos.c` with the stubs): bit-banged `i2c_change` transactions — write to a locked byte leaves `cmos.ram` unchanged and read-back returns the old value; unlocked neighbour and RTC store; sequential transfer across a locked/unlocked boundary and the address wrap; a guest checksum write stores the guest's value unchanged; empty set (RISC OS 2 class) stores everything. Harness: (a) a persisted `ARCCMOS2` record with non-zero locked bytes heals before execution (live image zeros, file rewritten normalised, one `CMOS: cleared` line, identity unchanged); (b) a raw hook write to a locked byte never appears in the record after `retro_run`, `retro_reset`, unload/reload, OS-class switch; (c) existing raw-216/raw-58 mutation, D-031 and SAVE_RAM-absence tests unchanged; (d) a project-authored guest exerciser ROM (extending `build_rom`) that drives the IOC I²C lines to write a locked byte, an unlocked marker and the checksum, reads back, branches through the reset vector and reports the result — the harness asserts the first-occurrence line once, the marker's survival and the locked byte's plugged read-back; (e) install session (A3020, IDE attach) keeps the IDE count and a valid checksum; (f) engine lifecycle through the real engine (a test hook exposing `arc_engine_reset`, or an engine-linked test): start → guest bus write/read → `arc_engine_reset` → write/read with an unlocked marker preserved and the lock still enforced; RISC OS 3-class start → stop (and a failed start) → RISC OS 2-class start with the formerly locked addresses writable; engine recreation preserving an attached IDE count; the first-occurrence diagnostic state scoped to the content session, not the engine instance. The exerciser ROM's fingerprint is registered under `ARCDROID_TEST_FAULTS` (`core/firmware_table.c:16`), never in the shipping table. CI: register the new tests in CMake and the sanitizer `-R` list; host, host-sanitizers, windows, windows-retroarch, android-arm64.
C-6 **Docs.** `docs/release-notes-slice13.md`: what changes (titles whose loader unplugs modules by a RISC OS 2 mask now boot on RISC OS 3; a title that had bricked its own settings recovers on the next launch), the rule and byte set in one paragraph, the log lines, the documented deviation (`*Unplug` does not survive a reset on RISC OS 3 in ArcDroid) and why (P-7; JASPP's ADFFS prevents persistent unplugging under its boot-floppy mode — supporting evidence, not the same mechanism), unchanged behaviours (RISC OS 2/Arthur sessions, configuration bytes, saves).
