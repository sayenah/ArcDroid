## Remediation after Opus QA (R-97…R-108)
- **R-99 (High, QA H-1) OSK chords must register in the guest.** On real RISC OS 3.11 an OSK activation with a one-shot or locked Shift produces no character although the KART trace shows Shift-down, key-down, key-up, Shift-up in order; a pad-held Shift across a pad key works. The chord's modifier is held for only ~2 KART polls. Make OSK activations guest-time paced: modifier down, then ≥ `ARC_OSK_HOLD_US` (default 60 000 µs guest time) before the key down, key held ≥ the same, then key up, ≥ the same, then modifier up; a held A extends the key phase; unmodified taps keep the same minimum hold. Constants in `core/osk.c`, unit-tested with the acknowledged-consumption model (guest time advanced by the test), and the harness asserts the guest-time spacing of the four edges in the KART trace. Evidence on real RISC OS is Fable's (R-100).
- **R-100 (Test, QA H-1) real-OS evidence path.** Add a harness mode `--osk-script <file>` to `tests/libretro_harness.c` (test build only) that, in `--real-boot` runs, executes a scripted sequence of OSK actions (open, tap key by RETROK name, set modifier state, close, wait N fields) and writes screenshots at the requested fields under `<dir>/evidence`. No ROM or disc bytes are checked in; CI does not run it. Fable uses it with the private ROM to verify `Shift+H` at the `*` prompt yields `H`.
- **R-101 (Medium, QA M-2) blank cursor-key glyphs.** `arc_osk_key_label` returns `<`/`>` for Cursor Left/Right but the font has no glyph at 0x3C/0x3E. Add authored left/right arrow glyphs (like the existing up/down) and a core test asserting that every glyph of every rendered label at both tiers is defined (non-blank) in `core/osk_font.h`.
- **R-102 (Medium, QA M-3) touch contact vs d-pad focus.** A d-pad move during a touch contact moves focus and the lift activates the focused key instead of the captured one. Freeze focus while a contact is captured (as during a held activation) and activate `contact_key` on lift; core test.
- **R-103 (Medium, QA M-4) per-port option names in the category.** `desc_categorized` drops the port, so the Pad Mapping category shows each input name twice. Use "Pad 1 Up" … "Pad 2 Select" for the categorized descriptions too; harness asserts the categorized strings are unique.
- **R-97 (Low)** header glyph capacity `(width-4)/8` with a long-name truncation test at 320 px. **R-98 (Docs)** PR body states the one-frame notice limitation is removed by R-94.
- **R-104 (Low, QA L-2) page key label.** Give the compact page key short distinct labels ("Pg2"/"Pg1") that fit the smallest cell, and include it in the uniqueness test.
- **R-105 (Low, QA L-3) option value id.** Rename the `(3,3)` value id from `hash_backslash` to `backslash` before it ever reaches a user's `.opt` (nothing is released); update tests.
- **R-106 (Low, QA L-4) reconcile comment.** Correct the comment in `core/input.c` that claims excess presses are re-sampled (they are not); no behaviour change required (unreachable in the shipping adapter, bounded by the static assertion).
- **R-107 (Layout decision, QA L-5) keyboard order.** The full tier is arranged in A3000 physical row order (Esc F-row; digits row; QWERTY row; ASDF row; ZXCV row; bottom row with Space; cursor/editing block and keypad to the right or on the second page); the compact tier pages preserve row order. Regenerate goldens; the uniqueness/fit/glyph tests still apply.
- **R-108 (Docs, QA L-6) omission list.** State the full set of unmapped engine cells ((0,13), (1,13), (3,10), (4,13), (6,8)…(6,15)) and that only £ and Print Screen correspond to A3000 legends.

Retracted: the suspected `.ldci` disk-control regression. Opus reproduced disc changes with and without the file; the earlier failures came from `DISK_NEXT` being silently ignored while the tray is closed, which a fixed toggle script hits when a restored index changes the starting phase. Device scripts must read the tray state from the OSD before each change.
