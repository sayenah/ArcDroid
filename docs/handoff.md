## Remediation (R-77…R-91)
- **R-77 (High) £ legend has no verified path.** `core/input_mapping.c` labels `RETROK_BACKSLASH` at KART (3,3) as "£" (option value `pound`, OSK glyph) and separately as "#/Backslash"; (3,3) is the `\ |` key after `]`, and the A3000 £ key is (1,13), which is unmapped in `keytable.h`. Remove the £ option value and OSK key, label (3,3) by its verified legend only (Backslash), list £ (and any other unverified legend) as omitted in the PR body, and make the provenance test fail on any label whose position is not the engine's for that alias. The handoff rule stands: omit and list, never relabel.
- **R-78 (Medium) duplicate events after overflow in aggregation.** `core/input.c` `arc_input_pad_key_sets` ignores the `arc_fifo_append` overflow/reconcile return in its four loops, so after a reconcile the remaining iterations append the same transitions again (duplicate key-downs, extra generation bumps). Stop appending once a reconcile has rebuilt the queue (as `arc_input_source_buttons` does); add a core test that overflows mid-loop and asserts no duplicate transitions and exactly one generation bump.
- **R-79 (Medium) no touch neutrality gate on OSK exit.** `arc_osk_restore_gameplay` only resets touch state; a contact still down at close becomes a fresh gameplay contact. Require the touch source to be neutral (no contact) before gameplay ownership returns, matching the pad gate; harness: close the OSK with a finger down, assert no gameplay click/motion until the contact lifts.
- **R-80 (Medium) right-hand modifiers send left codes.** OSK "Right Shift/Ctrl/Alt" keys toggle the left slot and emit `RETROK_LSHIFT/LCTRL/LALT`. Emit the right-hand codes (their `keytable.h` positions are verified) with their own sticky slots, or omit the right-hand keys and list them; no label may send a different key identity.
- **R-81 (Medium) focused key not locked during a hold.** `arc_osk_move` runs while `activation_held`; lock focus for the duration of an A hold as specified (harness: hold A, press d-pad, assert focus unchanged and release delivered to the original key).
- **R-82 (Low) release ordering on modal entry / mapping change.** `arc_input_clear_source` iterates RETROK codes ascending, so ordinary-before-modifier release is coincidental. Order releases by key meaning (ordinary releases, then modifier releases); assert it in a core test with a modifier whose code is lower than an ordinary key's (e.g. `RETROK_LSHIFT` vs `RETROK_z`).
- **R-83 (Low) OSK label overflow.** Clip labels to the key cell (compact cells overrun neighbours); shorten labels where needed ("KP Ent").
- **R-84 (Low) unreachable glyphs and header.** `arc_osk_text` maps bytes ≥125 to '?', so the arrow glyphs are unreachable; the "INTERRUPTED" header is cleared by `arc_osk_take_interrupted` before `arc_present` and never renders. Fix both; golden-test one arrow label and the interrupted header.
- **R-85 (Test) key provenance must enumerate against the engine table.** `tests/core_tests.c` only bounds-checks rows/columns and hard-codes OSK positions. Derive expected positions from `engine/arculator/src/keytable.h` + `plat_input.h` in the test (compile the table into the test or parse the header) and assert every catalogue and OSK entry's `(row, column)` equals the engine's for its RETROK alias. The PR body's AC-10 claim must match what the test does.
- **R-86 (Test) AC-1 digest path end-to-end.** Harness: register (via the test hook) a profile keyed on the generated application fixture's real digest and assert Auto resolves it (log source `[profile]`), that the same bytes under another filename match, that a different image with the same disc name does not, that a playlist matches only its set digest, and that identity stays frozen across a swap/eject in-session.
- **R-87 (Test) AC-9 OSK-typed sequence.** Drive an OSK typed sequence (sticky Shift then a key, then a plain key) and assert the order-sensitive guest signature differs from the reversed order; keep the KART-trace assertions.
- **R-88 (Test) AC-3/AC-5 gaps.** Harness: a legacy-only `.opt` simulation (GET_VARIABLE false for the 22 new keys) loads with defaults; assert `SET_VARIABLE` is never invoked (count environment calls); capability off → polled levels ignored (a polled-up held key stays held).
- **R-89 (Test) AC-6/AC-7/AC-8 gaps.** Harness: OSK entry with a stalled KART queue and mixed physical-mouse/pad motion (accepted events drain, no cancellation); busy state under stalled KART; Start closes; growth-failure during an activation asserts the held key's release is delivered and gameplay ownership restored; geometry change while the OSK is visible (relayout, no out-of-bounds under ASan); fix the touch-row arithmetic that assumes 7 rows for the 8-row full layout.
- **R-90 (Docs) accurate PR evidence.** Rewrite the AC evidence table so each row states exactly what the tests assert (no "enumerated against keytable.h" unless R-85 makes it true; no OSK-typed signature claim unless R-87 exists). List every omitted legend (£, Print Screen, positions (0,13)/(1,13), right-hand modifiers if omitted).
- **R-91 (Profile) real-title entry.** Add the entry only from Fable's PR-thread comment (digest, observed controls, evidence note). If none is posted by the time R-77…R-90 are done, push without it and state in the PR body that the slice remains profile-incomplete pending Founder input.

### Round 2 (Fable re-review of `df4d3c7`, 2026-09-15)
- **R-92 (Medium) compact-tier labels collapse.** At 320 px (10 columns, 30-px cells, 3 glyphs) every keypad key renders as "KP " and modifiers as "L S"/"R S"; at 640 px five glyphs. Give every key a distinct label per tier (e.g. compact `K0`…`K9`, `K/`, `K*`, `K-`, `K+`, `K.`, `KEn`, `LSh`, `RSh`, `LCt`, `RCt`, `LAl`, `RAl`, `Bsl`, `Cps`, `Ins`, `Hom`, `PgU`, `PgD`, `Del`, `Bks`, `Ret`, `Esc`, `Tab`, `Spc`, `Cpy`, arrows by glyph) and assert in a core test that no two keys share a rendered label at any tier; regenerate the goldens.
- **R-93 (Low) discriminating release-order test.** The R-82 test uses LSHIFT (304) vs `a` (97), which ascending-code iteration already orders correctly. Use a non-catalogue ordinary code above the modifier codes (e.g. `RETROK_BREAK`, accepted by `arc_input_source_key`) so the test fails on code-ordered release.
- **R-94 (Low) interrupted notice persists.** The "INTERRUPTED" header is presented for one frame because the surface is re-rendered every field. Hold the header (and the BUSY state) for at least 1 s of guest time or until the next OSK action, whichever is later; at 320 px show a short form ("INT", "BUSY") that fits after the profile name (truncate the name, never the state). Harness: after a forced reconcile during an activation, the header is visible on the presented frame 20 fields later.
- **R-95 (Low) touch focus during a held activation.** `arc_osk_touch` moves focus on a new contact while `activation_held`; freeze focus for touch as for the d-pad (core test).
- **R-96 (Docs) PR evidence accuracy.** Correct the rows for R-84 (golden sets the flag directly), R-82/AC-2 (test now discriminating per R-93), R-89/AC-8 (relayout asserted by visibility and ASan only, or add a layout assertion), and state the one-frame limitation is removed by R-94.
