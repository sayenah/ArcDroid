### Scope
1. **R-1 — no per-game `.srm`.** `retro_get_memory_size(RETRO_MEMORY_SAVE_RAM)` returns 0 and `retro_get_memory_data` returns NULL on every load path (native, ADFFS, zip, folder set, m3u, failed construction); the D-019 write-through file remains the only CMOS record and its lifecycle is unchanged (created on first construction, updated on CMOS change, re-read on the next load of the same identity). Every harness assertion that read the SAVE_RAM buffer is restated on the write-through file with the same intent (tag, mutation visibility, reset/reload persistence, identity separation). `docs/zip.md` gains the RetroArch scan note: "Scan Inside Archives" off = one playlist entry per zip; on = one entry per member, every entry boots image 1; and states that `.srm` files from earlier builds are inert and may be deleted. The Windows CI driver asserts that no `.srm` exists under the saves directory after a run.
2. **R-2 — CI driver hardening (test-only).** Bounded retry (named constant, ≥ 3 attempts) of the in-session reload step at `:327` and of the two `Move-Item` sites, retrying only on the "being used by another process" condition, with the attempt count in the log; a run that succeeds first time produces identical evidence to today.
3. **R-3 — zip member mode.** In `arc_zip_content_member`, a Unix-origin entry whose mode has zero file-type bits (`mode & 0170000 == 0`) is a regular file; entries typed as directory, symlink, socket, FIFO or device stay rejected. `zip-content` gains a fixture with a Python-style `0600` member (expected `images=1`) and a negative with a symlink-typed member (still omitted); `docs/zip.md` notes the rule.
4. Release-note bullets in the PR description: no `.srm`, the scan note, the zip-mode fix.
