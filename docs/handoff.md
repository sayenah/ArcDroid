## Work order — Slice 5c: launch chooser (D-039, D-042, D-047)
**Objective / governing requirement:** with Launch = Auto, a disc holding several launchable applications shows an in-frame pick-list before the machine starts; the pick launches, is remembered per content identity, and can be changed from the core options. PRD FR-4, FR-20, FR-22, FR-24, FR-26, FR-52; D-039 (no name vocabulary), D-042 (`!System`/`!Fonts`/`!Scrap` never launch candidates). UX accepted by the Founder 2026-09-20 (S16).

**Verified repo state (`main` `58cc2ac`):** the launch is frozen before `arc_engine_start` — `arc_prepare_launch` (`libretro/arcdroid_libretro.c` ≈1565–1681) runs discovery, applies `arcdroid_launch`, publishes the helper disc `<save>/arcdroid/launch/<content_id>.adl`; load (≈2987–3015) and `retro_reset` (≈3151–3173) seed CMOS (`arc_seed_cmos`, 662) whose boot-drive bytes depend on the helper (`core/cmos_defaults.c` 76–79) and start the engine; `retro_run` (≈3325–3336) always advances the guest when loaded; there is no pause. `arc_cmos_record` is the static SAVE_RAM buffer (3445–3446) and also holds the load-time seed; RetroArch 1.22.2 copies `.srm` bytes into it after `retro_load_game` returns (`runloop.c` ≈3955, `save.c` ≈324) — harmless today because the machine is already built. Discovery candidates = every `!`-prefixed root directory, ≤77, names ≤10 raw bytes (`core/launch_discovery.c` 467, 542–572; reasons 595–645); `core/launch_disc.c` 137–152 finds the resource and sibling boots in that same candidate array. `arcdroid_launch` = auto/off/app1…app8 addresses candidate ordinals (1596); the `.bind` guard compares exact target bytes (1483–1493). Core options are published once (2720), `SET_VARIABLE` is never used, `arcdroid_launch` is read only at load/reset. Mid-session geometry/timing changes already go through `SET_GEOMETRY`/`SET_SYSTEM_AV_INFO` (3365, 3392). OSK: `core/osk.c` 8×8 font without lowercase, several blank ASCII glyphs, bytes ≥128 drawn as `?`, slots 125/126 are arrows; only pad 0 and touch are gated while it is open.

**Scope**
1. **Target eligibility (D-042):** root directories named `!System`, `!Fonts`, `!Scrap` (ASCII case-insensitive, exact) stay inspected records — still booted first by the generated boot file, still in diagnostics, marked as resources — but are never launch targets: excluded from the application/unknown counts and reason ladder, from disc-name matching, from chooser rows and from `Application N` numbering (N counts the remaining candidates in order).
2. **Pre-boot chooser:** session states prepared → choosing → running (or failed). When Launch = Auto, the OS is supported, the mounted image is image 1, discovery has no target, the reason is `ambiguous` or `inspection incomplete`, at least one verified launchable application exists, and no applicable remembered choice is used, `retro_load_game`/`retro_reset` succeed without constructing the machine. While choosing, `retro_run` presents a core-owned 640×480 frame at 50 Hz with silent 48 kHz audio for each run and advances no guest time; the transition into and out of that mode (including a reset from another guest mode) is announced through the existing AV-info path inside `retro_run`. Rows: the launchable applications in discovery order, then `Desktop (no launch)`; an `inspection incomplete` notice when applicable; unknown candidates are never offered. Confirming constructs the machine through the same shared path load/reset use, from the CMOS seed captured privately at load/reset — frontend writes to SAVE_RAM made before construction must not reach the machine or the core's CMOS file; the public buffer address and size never change. If construction fails after a pick, the session ends as a failed reset does today, with a human-readable message. While choosing: serialization size 0, cheats inert, disk-control getters coherent, disk-control mutations refused without engine calls, no CMOS file writes, unload clean, option changes take effect at the next load/reset as today. Self-booting discs, a discovery target, `off` and `appN` never show the chooser and never read the choice record.
3. **Remembered choice:** `<save>/arcdroid/launch/<content_id>.choice` — strict, bounded, versioned text record holding the raw target bytes (or the Desktop marker) and the candidate fingerprint; written at confirmation, never at unload. Replay uses the same eligibility gate as the chooser and requires the recorded target to be a verified launchable application now (fingerprint change alone does not invalidate). An unreadable, invalid or unmatched record shows the chooser and is left byte-identical until a new pick is confirmed; replacement is recoverable (an interrupted replace leaves a valid old or new record, or none). If the record cannot be saved, the pick still launches with a visible "choice not remembered" notice. `.bind` format and guard are unchanged; parsing/IO primitives may be shared.
4. **Core option** `arcdroid_launch_chooser` = `remember` (default) | `ask`: `ask` shows the chooser at every eligible load/reset with the remembered row focused, and the confirmed pick replaces the record. The core never writes option values and no option value deletes files.
5. **Input while choosing:** pad port 0 (D-pad or left stick up/down, A or Start confirm), touch/pointer tap on a row, host keyboard Up/Down/Return. Navigation repeat, if any, counts `retro_run` calls, not guest time. No input from any port, keyboard, mouse or touch reaches the guest while choosing, and every control held at confirmation must be released before it can reach the guest.
6. **Rendering:** each row shows its number and the name; printable ASCII is drawn as itself including lowercase (add glyphs; do not reuse the arrow slots as literals), other bytes as the established `\xNN` escape; two different names never render identically; long lists scroll (up to 77 rows).
7. **Diagnostics:** the `Launch:` log line reports the chooser outcome (shown / remembered / asked, chosen target or desktop, resources marked); the old "set Launch to Application N" OSD remains only where the chooser does not apply.

**Non-goals:** name vocabularies or title tables; per-disc choices inside a set; a separate "forget" command or manage mode; native mouse navigation; CMOS/SRAM precedence redesign beyond item 2; lifting the 8-ordinal limit of `arcdroid_launch`; `.bind` changes; save states; self-boot JFD work; the listed follow-up Lows.
