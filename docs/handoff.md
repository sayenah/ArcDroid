### Scope
1. **Frontend contract.** `valid_extensions = "adf|adl|jfd|m3u|zip"`, `need_fullpath = true`, `block_extract = true`; `.info` `supported_extensions` adds `zip`. Content path forms: a path with extension `.zip` (case-insensitive); the member form `<archive>.zip#<member>` split at the first `#` that follows a `.zip`-terminated prefix (RetroArch's rule). Any other container the frontend may now hand over unextracted (`.7z`, `.rar`, …) fails with an actionable message naming `.zip` as the supported container.
2. **Shared reader** `core/zip.c` / `core/zip.h`: lift the 6a reader out of `core/adffs.c`; ADFFS calls the shared module with its existing limits. Caller-supplied limits (archive bytes, entries, member bytes). Two error classes: **archive-fatal** (structure) and **member-local** (one entry). Structure (fatal): EOCD located by backward scan and validated (comment length makes `eo + 22 + comment == n`); disk numbers 0 in EOCD and per entry; counts agree; no zip64 (sentinels, extra id 1 in either record); central directory within bounds and consumed exactly; every local header within bounds and consistent with its central entry (name bytes, method, flags, crc/sizes incl. the data-descriptor form); member data region must lie entirely before the central directory and must not overlap another member's region; names non-empty, < 256 bytes, no embedded NUL, `safe_name` rules (no leading `/`, no `\`, no empty/`.`/`..` components); extra fields in both records well-framed (each `id,len` fits) else fatal; where an extra id with consumed semantics (`ARC0`, id 0x4341) appears in both records its payload must agree — otherwise the local extra may differ freely from the central one (the only relaxation versus 6a). Flags: bit 0/6/13 (encryption, masked headers) fatal at the entry, bit 5 (patched data) fatal, bit 3 and bit 11 accepted, others ignored. Member-local: method not stored/deflate, or declared size above the caller's member limit → the entry is unusable (ADFFS keeps refusing the package; content omits or ignores per Scope 5). Extraction unchanged: exact declared-size buffer, inflate must consume exactly `packed` and produce exactly `size`, CRC32 verified.
3. **Content limits (D-054).** Archive ≤ 32 MiB (VFS size checked before the read; `arc_io_read_all` gains an explicit limit — every other caller keeps 16 MiB); ≤ 1024 central entries; uncompressed member ≤ 8 MiB (a qualifying member above it is omitted with reason `member-too-large`, never extracted); > 32 qualifying images or a prepared logical total above 256 MiB → **load fails** with an explicit message (no "first N" and no "selected alone" fallback); candidates are counted before any extraction. Non-qualifying members are never extracted.
4. **Member selection** (`core/zip_content.c`, reusing `arc_natural_compare` / `arc_media_extension` made non-static in `core/folder_set.h`): qualifying = regular file entry (no trailing `/`; external-attribute Unix mode, when present, is a regular file — symlinks/specials skipped), **no path component starting with `.`**, not under `__MACOSX/`, extension adf/adl/jfd case-insensitive, any depth, mixed formats allowed, names as raw bytes. Order: natural compare over the full member path, `strcmp` tie-break. Exact duplicate member names → archive refused. A `zip#member` reference must name an existing qualifying member (else load fails "`<member>` is not a supported disc image in `<zip leaf>`"); it **never changes** which disc boots or the identity: the set loads exactly as the bare zip (log `selected=<member>`).
5. **Preparation.** Members are extracted one at a time in order through a bytes-in variant of `arc_prepare_source` sharing every inspection/digest/staging/label rule (source string `<archive>#<member>`, label = member leaf stem, JFD title fallback). A qualifying member that fails (member-local reader error, media inspection, staging), including the first, is omitted (`Zip member omitted: member=<name> reason=<…>`) and load continues; none survive → `No usable disc image in <zip leaf> (<first reason>)`; none qualify → `No supported disc image (adf, adl, jfd) in <zip leaf>`. One log line per load `Zip content: file=<leaf> entries=<n> images=<k> prepared=<p> omitted=<m>[ selected=<member>]`; OSD summary when omitted > 0 (existing folder-set form). The archive buffer and each member buffer are freed as soon as they are no longer needed; the archive buffer never survives machine construction.
6. **Identity / persistence.** Unchanged digest code: a single-image zip has the unzipped file's `content_id`; a multi-image zip has image 1's (D-041 rule); staging, CMOS, `.choice`, `.bind`, helper disc and profiles key identically. `get_path` returns `<archive>#<member>`. For each zip entry record the member name, central CRC32 and sizes with the entry (for reset verification).
7. **Writes.** `Disk writes = Original` → zip members are prepared as **`Shadow`** (one log line + one OSD notice "Zip content is never written in place; writes go to the shadow copy."); `Off` and JFD immutability unchanged. The zip is opened read-only only.
8. **Reset** with a changed disk-writes option re-prepares zip members by re-opening the archive under the same limits and re-extracting by exact member name; the re-extracted bytes must match the recorded CRC32/size and the entry's digest, else that entry fails (image 1 → reset refused as today; others → omitted with the existing index remap). A removed or replaced archive is handled by the same rule.
9. **Playlists and disk control (non-goal boundaries).** `.m3u` entries that are zips or contain `.zip#` are refused before preparation with a message naming the rule; `replace_image_index`/`add_image_index` with a zip or `zip#member` path fails exactly like any other invalid replacement today (error message, existing slot handling).
10. **ADFFS.** Eligibility ladder unchanged (`multi-image` for several images; one qualifying JFD is eligible). The raw member bytes for a single-JFD zip are taken from the load pass (kept only when the zip has exactly one prepared image and it is a JFD within the carrier capacity; freed after `arc_prepare_adffs`), never re-read by name; the carrier's `$.Game` equals the JFD file bytes as unzipped. On the index-change call path nothing changes (ADFFS content is single-image).
11. **User note** `docs/zip.md` (short): what loads, order rule, skipped members and notices, limits, writes to shadow, `zip#member` behaviour, the RetroArch per-game-settings naming note (name the zip like the image, or use the member form, to keep frontend-side per-game overrides/remaps/options), `.m3u` cannot point at zips. `docs/adffs.md`: one sentence that a zip holding one JFD is eligible.

### Non-goals
`.m3u` entries pointing at zips or members; nested zips (non-media); zip64, encryption, other methods or containers; streaming reads; multi-disc ADFFS; SAF/URI claims; changes to folder-set or playlist behaviour; changes to `ARC_PLAYLIST_MAX_ENTRIES`; frontend-side settings migration; writing zip content anywhere but the existing staging tree.

### Architectural constraints
No frontend extraction dependency; no host file outside `<save>/arcdroid/media|launch|cmos`; the zip is never opened writable; no memory-source registration for content; no new third-party code (vendored zlib inflate only); project-authored fixtures with invented names only; no private content in the repository, CI, logs or PR; hidden visibility, `retro_*` exports only; `core/` stays free of libretro/VFS dependencies (the VFS read stays in `libretro/`); allocation lifetime budget for a load: archive ≤ 32 MiB + one member ≤ 8 MiB + one decoded JFD ≤ 8 MiB + one staging verification buffer ≤ 8 MiB, sequential per member, documented in a comment where the buffers are owned.
