## Architecture (D-056)
**Rule.** After qualification and the 32-image cap (unchanged), image 1 is the member chosen by the first tier that has at least one candidate; several candidates in the winning tier → the first by `arc_natural_compare` over the full member path (with its `strcmp` tie-break); a tier with no candidate is skipped:

- **T1 `disc1` — explicit disc 1.** Inspect only the member's leaf stem (leaf without its media extension). Token: `disk` or `disc`, ASCII case-insensitive, preceded by the start of the stem or a separator; then zero or more separators; then a complete decimal digit run whose value is 1 (leading zeros allowed, no integer conversion beyond that); then the end of the stem or a separator. Separators: space, tab, `.`, `_`, `-`, `(`, `)`, `[`, `]`. Accept `Disc1`, `(Disk 01)`, `disc-1`, `Disk 1 of 3`; reject `Disk10`, `Disk1a`, `HardDisk1`, `Side A`. If the same stem also contains a disc token (same grammar) with a value other than 1, the member is **not** a T1 candidate.
- **T2 `name` — zip-name match.** Zip key = archive leaf minus its `.zip` (case-insensitive) minus one optional media extension (`Title.jfd.zip` → `Title`). Member key = leaf stem. Equal under ASCII case folding, every other byte exact.
- **T3 `folder` — the D-041 shape inside the zip.** The member's complete leaf equals (ASCII case-insensitive) the complete name of its immediate parent directory in the archive, **and every qualifying member of the archive is directly inside that same parent directory**. Otherwise no T3 candidate.
- **T4 `order` — natural full-path order** (D-054).

The chosen member is moved to the front of the preparation list; every other image keeps natural full-path order. Preparation semantics are unchanged: if the preferred member fails preparation it is omitted and the first surviving member becomes image 1 (no re-run of the tiers). `zip#member` remains qualification-only. Identity, staging, shadows, ADFFS single-JFD ownership, reset order and all limits are unchanged.

**Interfaces.** `ArcZipContent` exposes the winning tier, the preferred member's index and the winning tier's candidate count; `arc_zip_content_index` receives the archive path (or leaf) to derive the zip key. The summary log line becomes  
`Zip content: file=… entries=… images=… prepared=… omitted=… rule=<disc1|name|folder|order> candidates=<n> preferred="<member>" boot="<member>"|boot=none fallback=<yes|no> [selected=…]`  
followed by one line `Zip content order: 1="<member>" 2="<member>" …` over the prepared set. Member names in these fields are double-quoted with `"` and `\` escaped as `\"` and `\\`. **Fallback OSD:** when the preferred member was omitted and a later member boots, the load's OSD summary is replaced by a warning that names the skipped member and the member that actually started (the counts summary is not shown twice); ordinary successful selection adds no OSD text. Per-member omission lines unchanged.

**Identity consequence (stated, not migrated).** Image 1's digest keys CMOS, `.choice` and profiles (D-029/D-041). Because T2 depends on the archive's file name, renaming an archive can change which member boots and therefore the set's identity, and a set zipped under 7a whose boot disc changes acquires the identity of the new image 1 (the same identity as the unzipped disc). No automatic migration: an old first-disc identity may legitimately serve another set. `docs/zip.md` and the release notes state both consequences.
