**Scope.**
C-1 **IDE import.** Add upstream Arculator `src/ide.c`/`src/ide.h` at the pinned commit `7d3d2679589bba759197e3a9288a12749c797381` (GPL-2.0-only; fetch from `https://github.com/sarah-walker-pcem/arculator`) to the allowlist with ArcDroid modification notices; update `engine/UPSTREAM.md` and `THIRD_PARTY_NOTICES.md`; replace the stubs. The core supplies a bounded block device (read/write of whole 512-byte sectors by LBA, success or failure); no `FILE*`, `fopen`, `fatal` or exit in the IDE path. Bounded CHS/LBA arithmetic (count register 0 = 256), mixed-width data-port access, command sequencing, absent drive 1, IRQ raise/clear and timer lifetime, reset, teardown, repeated sessions. **Writes:** WRITE SECTOR(S) (0x30/0x31) latch and validate the whole command, buffer the complete payload (≤ 128 KiB) through the normal per-sector DRQ/IRQ handshakes, and submit one transaction to the store before the final completion; a store failure ends the command with an error status and latches the session read-only for the IDE disc; reset, a new command, an invalid transfer or teardown discards an uncommitted buffer. FORMAT (0x50) and every other mutating or unsupported command return ABRT. When no disc is attached the IDE side must behave byte-identically to today's absent bus. Attach only on the **A3020** this slice (not A3010, not A4000).
C-2 **CMOS.** IDE count 1 (byte 135 bits 6–7) only in the per-session machine image of a session with an attached disc; persisted CMOS payloads keep it 0 (D-031 pattern).
C-3 **Formatter.** Project-authored FileCore new-map hard-disc formatter producing a blank disc of one fixed geometry: 512-byte sectors, 63 sectors/track, 16 heads, 32 cylinders (16 515 072 bytes), density 0; the probe's known-good layout is idlen 15, log2bpmb 10, zone_spare 32, 5 zones, map (two copies) at the start of zone 2's allocation, object 2 = a boot-block fragment in zone 0 plus map copies and root in zone 2, root indirect address `0x20B`, a "Nick" root directory, defect-list terminator `0x20000000` at 0xC00 and the boot-block checksum at 0xDFF. Geometry and formatter version are recorded in the store manifest. Never derive the disc from commercial media.
C-4 **Store.** `<save>/arcdroid/install/<storage-id>/`, storage-id = lowercase hex SHA-1 of a canonical string of the JASPP game id, the variant key and each numbered disc's decoded SHA-1 (no recipe revision; independent of zip/gzip/folder packaging; distinct from the chooser `plan.binding`). Owned names: `disc.g<N>.hdf`, `journal.g<N>`, `ready.a`, `ready.b`, temporaries `disc.g<N>.hdf.tmp`, `journal.g<N>.tmp`, `ready.tmp`. **Manifest** (`ready.a`/`ready.b`, checksummed): format version, storage-id, geometry, formatter version, recipe revision, generation N, base file name, base SHA-256, journal file name. **Journal** file = a checksummed file header {magic, version, storage-id, generation, base SHA-256} then records: fixed header {magic, version, storage-id binding, generation, sequence, first LBA, sector count, payload length, header checksum} + payload + fixed trailer {sequence, payload checksum, commit magic}; each IDE write command is appended and flushed through the VFS before the command completes (per-command atomicity under process kill; no power-loss claim; FileCore multi-command saves are not atomic).
 **States, in precedence order.** (1) At least one committed slot present → every present slot must be valid (unreadable, truncated, malformed, foreign storage-id or unsupported version → DAMAGED even if the other validates; equal generations → DAMAGED); select the higher generation; its base hash must match and its journal replay, else DAMAGED; other generations and temporaries are ignored at load and cleaned only in writable mode. (2) No committed slot, every file an owned generation-0 name (`disc.g0.hdf[.tmp]`, `journal.g0[.tmp]`, `ready.tmp`), and any `journal.g0` is a valid **header-only** journal (a `.tmp` no longer than a header) → UNPUBLISHED: writable mode deletes them and recreates a blank candidate; read-only mode fails. (3) Directory absent or empty → NEW (writable: create; read-only: fail). (4) Anything else → DAMAGED. DAMAGED always fails the launch with an actionable message and leaves every byte untouched.
 **Creation and first publication.** `disc.g0.hdf.tmp` (blank) → verify → rename `disc.g0.hdf`; the install session writes this candidate in place (no journal before publication). Publication (C-5): flush the base and compute its SHA-256; `journal.g0.tmp` (header only) → verify → rename `journal.g0`; `ready.tmp` → verify → rename `ready.a`.
 **Replay.** EOF inside a record header → incomplete append. For a complete header validate checksum, version, binding, generation, sequence = previous + 1, 1 ≤ count ≤ 256, LBA + count ≤ disc sectors, payload length = 512 × count — any failure → DAMAGED; only then may EOF inside its payload or trailer be an incomplete append; a complete trailer with wrong sequence, checksum or magic → DAMAGED. Writable mode truncates an incomplete append; read-only mode ignores it in memory. After any append or flush failure the session refuses further IDE writes (guest error) and says so.
 **Compaction** only at load in writable mode when the selected journal exceeds 1 MiB: write `disc.g<N+1>.hdf.tmp` = base + replayed journal → verify → rename; `journal.g<N+1>.tmp` (header only) → verify → rename; delete the **unselected** slot file (never the selected one); `ready.tmp` → verify → rename to that now-free slot name; only then remove generation-N files (failures logged, ignored). In-session journal cap 8 MiB: further writes fail with a guest error and a notice.
C-5 **Launcher plans and publication.** Stage 1 unchanged. **Install plan** = the Slice 9 stage 2 unchanged up to the RAM install, then `Copy RAM::0.$.<app> ADFS::4.$.<app> ~C~VRFQ` with an `IfThere` guard, copy the ArcDroid-authored marker `ADFS::1.$.ArcReady` → `ADFS::4.$.ArcReady` (content: an ArcDroid string including the storage-id), `Dismount :4`, then `*Load` the doorbell file `ADFS::1.$.ArcDoor`, which the support-disc builder places alone on track(s) used by no other object. **Doorbell** = the first guest READ SECTOR controller command (WD1772 or 82C711) addressed to drive 1 for an `ArcDoor` sector — detected at the controller command layer, never from track-buffer or host-file reads; tests prove no earlier launcher read addresses those sectors.
