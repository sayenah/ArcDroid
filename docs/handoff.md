## Input Slice work order (candidate, pending Astra)

### Scope
1. **Controller-driven pointer (new, D-026).** Port 0 default device (`ARC_DEVICE_KEYS`, a `RETRO_DEVICE_JOYPAD` subclass) additionally drives the Archimedes mouse: right analog stick = pointer velocity (dead zone, monotonic response curve, per-frame delta accumulation with sub-pixel remainder, clamped to the KART ±63 packet range per poll without losing motion); default buttons R1 = Select, L1 = Adjust, L2 = Menu, R2 = pointer slow/precision modifier. Existing RetroPad→key mapping (d-pad arrows, A Space, B Return, X Shift, Y Ctrl, Start Escape, Select Tab) is unchanged. Core options: `arcdroid_pointer_stick` (right / left / disabled), `arcdroid_pointer_speed`, and button assignment stays remappable through RetroArch (FR-33); input descriptors and `SET_CONTROLLER_INFO` updated so RetroArch shows the new bindings. Analog reads are serviced by RetroArch regardless of the port's device type (verified 2026-09-14 in `input/input_driver.c`, `input_state_internal`); the only gate is RetroArch's analog-to-d-pad mode on the converted stick, so the default pointer stick is the **right** stick.
2. **Defect 1 — touch is a trackpad, not a held Select.** In `arcdroid_pointer_mode = relative` a contact that moves is pointer motion with **no** button; a tap (contact shorter than a threshold with movement under a threshold) is one synthetic Select click held for at least one full keyboard-poll cycle; a two-finger tap or long-press is Menu (design choice for Astra). Today every contact sets `mouse_buttons = 1` (`core/input.c` `arc_input_pointer`), so every move is a Select-drag.
3. **Defect 2 — pointer cannot enter the icon bar.** Observed on the Odin3 desktop: RISC OS `MOUSE` reports the pointer stopping at Y = 132 OS units (33 lines = the icon-bar height) while the Wimp runs; with the desktop suspended (F12 BASIC) the pointer reaches Y = 0; after `OS_Word 21,1` with a full-screen box the desktop pointer also reaches Y = 0 and the icon-bar click works. Leading hypothesis: the held-Select touch semantics start a Wimp/Pinboard drag whose parent box excludes the icon bar and the box is not restored. Sol must re-test after Scope 2 with correct hover semantics; if the clamp persists it must be root-caused in the emulator/adapter (no guest-side `OS_Word` workaround).
4. **Defect 4 — keyboard events shorter than one poll are lost.** `arc_keyboard` writes level state that `keyboard_poll` samples every 10 ms guest time; a press+release inside one sample vanishes (adb typing lost most characters until paced at 0.2 s). Queue keyboard-callback and synthetic pointer-button events FIFO and hold each level for at least one full engine keyboard-poll cycle (modifier-before-key ordering preserved, no reordering between keyboard and mouse-button events). Same latch serves Scope 2 taps.
5. **ADFS recognition message.** `arc_media_is_recognised_adfs` only checks old-map sector checksums, so every E/D-format (new-map, `Nick` directory, disc record at byte 4) disc logs "Media is not a recognised ADFS image; booting anyway". Recognise new-map discs (disc record sanity + map/root signature) and keep the message for genuinely non-FileCore images.
6. **Prior baton item 7 loose ends (low):** harness asserts the R-36 2 s threshold against the constant instead of a 1.0–3.6 s bracket; stale comment `tests/generate_fixtures.py:239` ("must receive a warning") vs R-36; pin with a test that the faulted-frame path emits no VIDC message; `tools/check-android.sh` / `tools/check-windows.sh` assert no non-`retro_*` export in addition to the count.

### Architectural constraints and affected interfaces
- Everything stays inside the existing libretro adapter and `core/input.c`; the engine contract (`arc_run_frame`, KART packet path in `engine/arculator/src/keyboard.c`) is unchanged except where a latch must sit at the engine boundary. Emulated time stays authoritative; input is sampled once per `retro_run`.
- No new exported symbols; the 25 `retro_*` exports and the shipping-I/O/no-test-hook guards (D-021) still pass. Test hooks only in `arcdroid_libretro_test`.
- Core options v2 remain the only configuration surface; defaults must give a playable mouse-driven title on a stock Odin3 with no options changed. Input descriptors must reflect every default binding.
- Windows: identical behaviour with a physical mouse (`RETRO_DEVICE_MOUSE` path) and with an XInput pad. Android: touch reaches the core only through RetroArch's pointer device (FR-32); no Android-side code.
- Deterministic tests must not depend on private firmware; RISC OS-level behaviour (icon-bar reach, Chess3D) is local Founder/Opus evidence.

### Acceptance criteria
- AC-1 With a stock RetroPad on port 0 and no option changes, the right stick moves the Archimedes pointer in all directions with a dead zone, and R1/L1/L2 produce Select/Adjust/Menu; RetroArch's input descriptor list shows these bindings.
- AC-2 A stick held at full deflection produces a bounded, monotonic per-frame delta (no ±63 wrap, no dropped motion at the KART packet limit); releasing it stops motion within one frame.
- AC-3 Touch move produces pointer motion with **no** button; a tap produces exactly one Select press/release pair that the engine observes as down for ≥ 1 keyboard-poll cycle; no spurious drags.
- AC-4 Every keyboard-callback press/release pair, including one delivered within a single `retro_run`, is observed by the engine as a down then up; ordering across 100 randomised key/mouse-button events is preserved.
- AC-5 On the Odin3 with RISC OS 3.11 (private, local only): the pointer reaches the icon bar and clicks an icon-bar icon using only the built-in controller; MicroPower Chess 3D can be launched from the desktop and a piece moved with the controller; the same is repeated with touch (tap/drag semantics). If the Y = 132 clamp is still reproducible with correct button semantics, the root cause is documented with evidence before merge.
- AC-6 E-format 800 KiB and D-format discs load without the "not a recognised ADFS image" message; the old-map generated fixture and a random-byte image still behave as before.
- AC-7 Host `ctest`, Windows load harness, Android/Windows/export guards and CI stay green; no new exported symbol; 100-cycle lifecycle still leak-free.
- AC-8 Scope 6 items closed with tests or documented as intentionally unchanged.

## Known limitations and follow-ups (after the Input Slice)
1. **Launch automation** (PRD north star): both Founder discs have boot option 0 and stop at the desktop; ArcDroid needs a policy to run the game application automatically (root `!App` discovery, `!Boot`/`!Run` dispatch, per-title override). Slice 2 architecture item.
2. Truncated dumps (Repton 4: 814 080 bytes for an 800 KiB E-format disc whose disc record says 819 200) are rejected by exact-size geometry; decide tolerance/padding policy with Slice 2 readers.
3. RetroArch Android delivers keyboard events to cores only from devices whose source is exactly keyboard (or keyboard+d-pad) or that match `input_android_physical_keyboard`; RetroArch hotkeys consume letters unless game focus is on. Document for players; nothing for the core.
4. First RetroArch launch this session died after ~37 s (no tombstone) while an unrelated app crashed and shared storage briefly disconnected; not reproduced in three later launches. Watch during the next device runs.
5. Audio 50 ms `pollsound` underruns at mode changes (D-022); host `ctest` never dlopens the shipping library; harness concurrency; `arcdroid_os` override gaps; 16 KiB-page runtime check — all as in the prior baton.
