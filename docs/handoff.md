### Scope
S-1 **Media inspection.** A 1 638 400-byte raw image is `ARC_GEOMETRY_1600K_F` (new media kind, extension `adf`). Descriptor recognition when the boot-block disc record (offset 0xDC0) is F-format (log2secsize 10, secspertrack 10, heads 2, density 4, idlen 15, log2bpmb 6, nzones ≥ 2, disc_size 1 638 400; boot option and disc name from it); otherwise size fallback (FR-7). Exact size only. The old 1600 K refusal disappears. Zip, folder-set, m3u and `zip#member` behaviour unchanged apart from the image now being supported; `docs/zip.md` gains one line.
S-2 **JFD parser.** Density 4 accepted; density 8 refused ("octal density unsupported"); untimed cadence 16 µs/byte at density 4. Everything else unchanged (deltas, whole-track, size codes, timed/untimed mixing, ID-only, CRC flags, 8 MiB caps). Identity unchanged (D-029).
S-3 **JFD reader contract on both controllers** (`disc_jfd.c`): READ ID completes through `fdc_funcs->sectorid` when the controller provides it (82C711) and through the byte path otherwise (WD1770, byte-identical behaviour); on the 82C711 a search that finds no matching sector (wrong density including an ED probe, absent id, empty or absent track-side, ID-only sector on a data read) terminates with `fdc_funcs->notfound` after **two index pulses** from the start of the search — the 765-class rule (SMSC FDC37C78 datasheet, ST1 MA: "did not detect an ID address mark … after encountering the index pulse from the IDX pin twice"; text copy in the S25 scratchpad `s8/fdc37c78.txt`), pinned by the golden test; the WD1770's own five-index RNF timer is unchanged; the reader stops its own state before any terminal callback so no completion is delivered twice; density mapping 82C711 rate 0 (500 kbps) ↔ JFD 4, rates 1/2 (300/250 kbps) ↔ 2, rate 3 (1 Mbps) ↔ 8 (never matches; the probe must still terminate normally) — rate encoding per the same datasheet Table 11 and `82c711_fdc.c:462-472`, WD1770 latch DD ↔ 2 / SD ↔ 1 unchanged; the revolution phase advances by the controller's current poll period (32/16/8 µs) so one revolution is 200 ms of guest time at every density; timed times, untimed schedules, ID-only and CRC-flagged sectors keep their semantics at HD. No allocation, file I/O or parsing in the poll path (D-028 reader rule).
S-4 **Engine raw media.** `ARC_GEOMETRY_1600K_F` loads through the upstream HD ADF loader (10 × 1024 B, two sides, density 2) on any drive; the drive-1 launch helper stays a DD L/D disc. The raw reader's index pulse is currently every 6 250 polls (`disc_adf.c:286-290`), which is 200 ms only at the 32 µs DD period and 100 ms at HD: make the raw reader's rotation elapsed-time based (200 ms at every poll period, DD behaviour and the WD1770 results unchanged). Upstream files keep their ArcDroid-modification notices (`engine/UPSTREAM.md`).
S-5 **Machine policy (D-061).** Option parsing is separated from machine resolution everywhere (`arc_read_options` `libretro/arcdroid_libretro.c:375-430`, reset `:4572`, runtime option updates `:4787`): options carry the *requested* machine; the *resolved* machine is computed once per load after every image of the session is prepared, frozen for the session (reset, disk swaps, removal of the sole HD sibling and runtime option updates never change it; an explicit machine change through options takes effect only at the next load or reset as today), and CPU/OS/joystick overrides and the firmware search (D-036 filter, FR-16 messages including missing New-IO firmware) validate against the resolved machine. `Auto` resolves after media inspection. If any prepared image of the session (image 1, folder-set siblings, playlist entries, zip members) is high-density, `Auto` = A3020 (the probed machine; A4000 is identical in ArcDroid but was not probed, A3010 adds joystick semantics); otherwise A3000 (D-013). Disk control: `arc_disk_add` carries no image, so the capability check runs in the replacement preparation that follows (`:2915-2932`) and on refreshed insertion: an HD image prepared into a WD1772 session is refused with reason `hd-media-needs-new-io` and a notice, a rejected replacement keeps the populated slot, a rejected append removes its empty slot; inserting an HD sibling in a New-IO session works. Logged once per load: `Machine: requested=<option> resolved=<name> reason=hd-media|default|option`. Content identity (D-029), CMOS keying (D-019), launch records (D-031/D-047) and title profiles unchanged; the New-IO firmware filter and FR-16 messages (D-036) apply as today.
S-6 **Discovery on F-format** (raw and JFD) and old-map tolerance. Bounded validation contract before any map use: boot-block record consistent with the media size (disc_size = 1 638 400, log2secsize 10, secspertrack 10, heads 2, idlen 13..15, log2bpmb 6..10, 1 ≤ nzones ≤ 8, zone_spare ≤ 8192−480−(idlen+1)); map address = Σ zone sizes below zone nzones/2 (zone 0 reduced by the 480-bit record) must lie inside the disc with nzones sectors of map plus the backup copy; each block's ZoneCheck, the CrossCheck XOR over all blocks, free links and fragment id/terminator scans bounded by the block; the final zone truncated at disc_size; every resolved extent bounded by disc_size. Backup fallback also when a primary map sector is unreadable (sparse JFD), never mixing copies. Then: reader geometry 10 × 1024 at density 4 (JFD) / raw F; new map generalised to nzones map blocks at the start of zone nzones/2, zone 0 shortened by the disc record, per-block ZoneCheck, `log2bpmb` range including 6, fragment resolution as FileCore does it (corroborated by Linux `fs/adfs/map.c`, read for facts only, no code copied): the search for fragment id F starts in zone F / ids_per_zone (fragment 2 — boot block, map and root — starts in the middle zone nzones/2) and wraps cyclically through every map block, so a fragmented object's pieces are ordered by that traversal, not by zone number; shared-offset (sector-within-fragment) addressing kept; primary map validated first (ZoneCheck per block, CrossCheck XOR over blocks); if it fails and the backup copy (the next nzones sectors) validates completely, use the backup and log the fallback; never mix blocks from the two copies; the declared old-map sector count is advisory: a count above the geometry's physical count (3200 D, 2560 L) is clamped to the physical count with one log line instead of a refusal; every read stays bounded by the physical geometry and a missing or ambiguous sector stays a failure (nothing is fabricated from the declared count). Entry tolerance, candidate rules, chooser and helper disc unchanged (D-039/D-041/D-047).
