## Scope
### A. Input mapping model and profiles (core/, adapter)
- **Mapping**: total function from the ten assignable inputs {Up, Down, Left, Right, A, B, X, Y, Start, Select} per port to `key <RETROK>` | `unbound`. R/L/L2/R2 and the pointer stick stay pointer controls (D-026); L3 is the OSK toggle; R3 reserved.
- **Profile** (compiled table `core/input_profiles.c`, no runtime parsing, no external file — D-033): stable preset id, display name, one or more verified D-029 digests (aliases), optional launch-target constraint (Slice 2b leaf name; the profile applies only when the launch decision selected that target), port-0 mapping, optional port-1 mapping, evidence reference. Unit-validated (unique digests and ids, supported RETROK codes only).
- **Generic mapping** = the current table. Unknown content always gets it (FR-48).
- **Resolution** (pure `core/` function): per input, (1) per-input option ≠ Auto, else (2) profile mapping when `arcdroid_input_profile = Auto` and a digest matched (or the user-selected preset), else (3) generic. Evaluated at load, at `retro_reset`, and live on any input option change; never on disk swap/eject/playlist edit (identity frozen, D-029).
- **Per-source aggregation**: each port's held bindings are combined into the complete desired key set before edges are emitted (two inputs on one key: the key stays down until both are released); transitions are ordered by key meaning across both ports: modifier presses, ordinary presses, ordinary releases, modifier releases (replaces the positional 6/7 rule). On a mapping/device change the old contribution is released, the new mapping installed atomically, and an input must return to neutral before it acts again. `core/input.c` overflow reconstruction becomes modifier-aware (modifier presses queued before ordinary presses); the adapter's FIFO capacity assertion is re-derived from the distinct supported key universe plus OSK needs.
- **Options** (static, categories via options v2 `categories`): `arcdroid_input_profile` {Auto, Generic, <one value per shipped preset id>} default Auto; `arcdroid_pad{1,2}_{up,down,left,right,a,b,x,y,start,select}` (20) {Auto, Unbound, <curated key list>} default Auto, category "Pad Mapping"; `arcdroid_osk_toggle` {L3, R3, Off} default L3. Curated key list (fixed, same for all 20, ≤ 128 values): letters, digits, Space, Return, Escape, Tab, Backspace, Delete, Copy, Insert, Home, Page Up, Page Down, cursor keys, Left/Right Shift, Left/Right Ctrl, Left/Right Alt, Caps Lock, F1–F12, `` ` `` `-` `=` `£` `[` `]` `;` `'` `#`/`\` `,` `.` `/`, keypad digits and operators, keypad Enter — each only if its label→alias→KART position is verified (see D). `arcdroid_joystick_if` unchanged. Auto is stored as Auto; `SET_VARIABLE` is never used.
- **Transparency (FR-34)**: one INFO line per resolution listing each input's effective action and its source; one OSD notification at load when a profile or preset applied ("Controls: <name>"); descriptors re-sent after every resolution with effective labels (strings adapter-owned, valid until unload); the OSK header shows the effective profile name and "custom" when any per-input option is not Auto.
- **Keyboard snapshot reconcile**: when the frontend reports keyboard polling capability (`GET_INPUT_DEVICE_CAPABILITIES` bit for `RETRO_DEVICE_KEYBOARD`), the adapter reconciles the complete supported key snapshot from `RETRO_DEVICE_KEYBOARD` after callback processing each frame, including the `RETROK_MENU`/`RETROK_LMETA` Menu-button latches: a polled-down key not held by the KEYBOARD source is pressed, a held key polled up is released, merged into the same source (no second latch). A callback tap completed within one frame is preserved (its release is already queued). Without polling capability the callback-only behaviour is unchanged. This recovers both a release lost while the RetroArch menu was open and a key still physically held on resume.
- **Shipped profiles**: at least one locally verified real-title profile with gameplay evidence is required for the slice to be complete: Repton 4 from the Founder's short dump (Fable supplies its D-029 digest and the observed controls in the PR thread during checkpoints 1–2; Sol adds the entry in checkpoint 3). Saloon Cars Deluxe only if its keyboard controls are confirmed. No entry from memory or web claims (FR-51). If the Repton 4 evidence is not obtained, the slice is reported incomplete, not shipped mechanism-only.
### B. On-screen keyboard (core/osk.c model + renderer; adapter compositor)
- **Toggle** L3 (option). Modal for port-0 pad and touch while visible. **Entry boundary**: new pad/touch contributions stop; the PAD0 and TOUCH sources' keys and buttons are released through the normal queued releases; events already accepted into the FIFO (including motion, which carries no source identity) drain normally — there is no source-selective cancellation of queued events; ownership returns on exit only after the pad/touch inputs are neutral. Physical keyboard, mouse devices and port 1 unaffected; RetroArch hotkeys unaffected (frontend-side).
- **Controls** (each sampled input has exactly one OSK action): d-pad moves focus with bounded guest-time repeat (no catch-up after a pause); A = key down while held, up on release (focused key locked during the hold); B = close; X = Backspace shortcut; Y = Return shortcut; Select = transparency; Start = close; page switching is done through focusable page keys on the layout (no shoulder button pages); the configured pointer stick (right by default, left if so configured) is reserved exclusively for an optional OSK cursor with R = select, L/L2/R2 unused; when the pointer stick is Left, the left stick moves the cursor and never focus; touch = absolute hit-test with the contact captured until release; offscreen contacts rejected; two-finger Menu gesture suspended.
- **Key set**: the Archimedes A3000 keyboard legends, including £ and Copy, function keys, cursor/editing keys and the numeric keypad, on one or two pages; no Windows keys; a key is present only when its RETROK alias and KART position are verified from `keytable.h`/`plat_input.h` (known gaps: `KEY_PRTSCR` absent from `keys[]`, positions (0,13)/(1,13) unmapped). Physical key identities only, never characters.
- **Modifiers** Shift/Ctrl/Alt: off → one-shot → locked → off, shown visibly, applied around an activation (never an invisible held modifier between activations). Caps/Num/Scroll Lock are ordinary guest keys.
- **Delivery**: new `ARC_INPUT_SOURCE_OSK` through `arc_input_source_key`; a bounded OSK action state machine with one outstanding activation, admitted only when the FIFO has room for its releases (busy indicator otherwise); progress driven by acknowledged consumption, not frame counts. **Completion rule**: a step whose effective level already matches because another source holds the key (e.g. physical Shift held while the OSK emits Shift+A) completes immediately without waiting for an edge and without releasing the other source; the OSK's own source contribution is still recorded so its later release is a no-op on the effective level. `core/input.c` exposes a reconcile generation counter; an outstanding activation whose generation changed is invalidated → releases recovered, interruption reported once, no silent replay. Close cancels unstarted work and completes releases without touching other sources; the guest performs autorepeat.
- **Rendering/compositing**: pure renderer into a caller-supplied XRGB8888 surface (width, height, pitch) using a project-authored 8×8 bitmap font (`core/osk_font.h`, drawn for ArcDroid, includes £ and arrows; no imported glyphs). The adapter composites immediately before `video_cb` into an adapter-owned scratch surface allocated at load for the visible geometry, grown within 4096×2048, freed at unload, copying visible rows only with the source pitch; engine pixels are never modified; `arc_can_dupe` only when the complete presented image is unchanged; drawing and hit-testing clipped; layout and contacts invalidated on geometry change; the OSK spans the visible width over the bottom ≈45 % with a paged compact layout for 320–639 px and the full layout at ≥ 640 px; below 320 px visible width controller typing is unavailable in that mode (one message on toggle, recorded limitation — the engine accepts smaller geometries); two alpha levels. **Presentation failure** (initial allocation or growth during an activation) → one actionable error, the OSK completes its outstanding releases, clears sticky/contact state, returns gameplay ownership through the neutral gate, presents a clean guest frame, and stays disabled for the session; gameplay unaffected.
- **Lifecycle**: visibility and focus survive frontend pause; `retro_reset` closes it and clears all OSK state; disk swaps preserve it; unload frees everything; 100-cycle lifecycle with toggling leaks nothing.

## Acceptance criteria
- **AC-1** Resolution: for every input and port, option ≠ Auto wins over profile, profile over generic; `Generic` ignores profiles; a preset selection applies without a digest match; unknown content resolves to generic; identical bytes under different names match, different bytes with the same disc name do not; a JFD recompressed with different gzip framing matches; a playlist matches only by its ordered set digest; identity is frozen across swap/eject/playlist edit; reset and live option changes re-resolve. (core_tests + harness)
- **AC-2** Aggregation and ordering: two inputs bound to one key hold it until both release; a modifier bound to any input is pressed before and released after ordinary keys in the same frame, across both ports; a mapping change while inputs are held releases the old keys and produces no new action until the inputs return to neutral; delivered order proven by the order-sensitive guest signature (AC-9). (harness)
- **AC-3** Options: 33 definitions asserted by key; categories present; per-game `.opt` values round-trip (harness simulates GET_VARIABLE); a file containing only the legacy 11 options loads; Auto is never rewritten. (harness)
- **AC-4** Transparency: resolution log line, single load notification when a profile/preset applies, descriptors re-sent with effective labels after load, reset and option change, OSK header status. (harness)
- **AC-5** Keyboard snapshot reconcile: with polling capability reported, a KEYBOARD-source key polled up is released within one frame and a polled-down key not held is pressed (menu-open release loss and held-on-resume both recovered), including the Menu/LMeta latches; a same-frame callback tap is preserved; without the capability nothing changes; no effect on OSK or pad sources. (harness)
- **AC-6** OSK controls: L3 (and R3, Off per option) toggles; entry releases PAD0/TOUCH contributions and drains already-accepted events (tested with a stalled KART queue and mixed physical-mouse/pad motion); while visible port-0 pad and touch produce no gameplay events; focus navigation with repeat in guest time and no catch-up after a skipped interval; A hold/release delivers down then up; B and Start close; X/Y shortcuts; page keys; touch hit-test selects the key under the contact and a drag off the key does not activate it; pointer-stick cursor with R (if implemented) with the left-stick configuration never moving focus; neutral-before-return on close. (harness, core_tests)
- **AC-7** Modifiers and typing: one-shot and locked states deliver modifier-before-key and key-before-modifier release; a chord admitted only with FIFO room; busy state under a stalled KART (keyboard disabled) and delayed acknowledgement; a step whose key another source already holds completes immediately and the other source is never released; repeated forced reconciles during one session each invalidate the outstanding activation (generation counter), recover releases and report; close during an outstanding activation completes its releases; no key from another source is touched. (core_tests, harness)
- **AC-8** Rendering: golden SHA-1 of the presented frame for at least 320×256 (compact pages), 640×256 and 640×480 visible geometries, both alpha levels, every page; a 256-px-wide geometry refuses with the message; engine buffer bytes unchanged after compositing; `video_cb` receives non-NULL while the OSK is visible or when it opens/closes over a duplicated field; frame duplication resumes only when the presented image is unchanged; geometry change while visible re-lays out without out-of-bounds writes (ASan); scratch surface freed at unload; simulated allocation failure at load and simulated growth failure during an activation both yield the error, complete releases, restore ownership and present a clean frame. (harness, sanitizer job)
- **AC-9** Order-sensitive guest evidence: `tests/generate_fixtures.py` gains a keyboard-receive path in the test ROM that folds every received KART key code into an order-sensitive signature painted into the frame; harness sessions assert distinct signatures for modifier-then-key versus key-then-modifier and for OSK-typed sequences. (harness)
- **AC-10** Key set provenance: every OSK key and every curated option key maps to a verified `keytable.h` position; the unit test enumerates the set; the PR lists any Archimedes legend omitted and why. (core_tests, PR)
- **AC-11** Lifecycle: 100 load/unload cycles with the OSK toggled and options changed show no leaks or growth; reset closes the OSK and clears state; menu/pause simulated by a frame gap leaves no stuck key or repeat burst. (harness)
- **AC-12** Local (not CI; Fable/Opus): (a) Odin3 — Repton 4 plays from the pad with its shipped profile (required for completion); a real RISC OS text field accepts OSK-typed text with edits and a modifier; physical sticks, L3, touch, a RetroArch keyboard overlay, a RetroPad remap and Save Game Options, menu/background/resume, ten reloads; Chess 3D pointer play unchanged; (b) Windows PC when available — keyboard/mouse/XInput coexistence with the OSK (D-024); (c) Retroid Pocket carried.
