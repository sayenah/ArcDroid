## Slice 5a work order — launch robustness (PRD FR-4, FR-5, FR-6, FR-7, FR-25, FR-34; D-030, D-031)
**Objective:** a loaded game disc starts its game without desktop interaction wherever that is deterministically possible, with no title database and no mutation of user media (D-014). **Branch:** `slice/05a-launch-robustness` from `main`; one PR.
**Astra:** blind pass + comparison pass 2026-09-19; every material finding incorporated (uncertainty model, raw-byte names, helper-only prohibition, label rule with unknowns, conflicting-name rejection, explicit target boot, alias-proof commands, no silent boot-list cap, binding absence semantics, allocation invariant, Auto-only self-boot rule). Reports are attached to the governance PR.
**Verified repo state:** `core/launch_discovery.c:380-450` fails a whole directory on a top-bit name byte, attribute bits 6–7 or any entry's extent, and its old-directory loop stops reading attribute bits at the name terminator; `arc_candidate_name` (`launch_discovery.c:465`) and `arc_launch_name_valid` (`core/launch_disc.c:33`) both whitelist ASCII; `arc_normal_name` drops non-ASCII; discovery's E-map size equality is stricter than `core/launch.c:78`; `core/launch_disc.c:101-129` has a 256-byte script buffer and allocates exactly two sectors; the binding parser (`libretro/arcdroid_libretro.c:1134-1165`) is a loose `sscanf` and treats a failed read as absence; the selected decision is logged unescaped.
**Scope and constraints**
- Discovery stays a bounded read-only root + one-level probe; no recursion, no host interpretation of guest scripts; all arithmetic overflow-safe; structural failures (markers, sequence bytes, map checksums, bounds, JFD CRC) fail the inspection as today. The E-map size invariant is shared with `core/launch.c` (bounded excess allowed).
- Names are guest bytes with explicit length everywhere (matching, fingerprints, bindings, profile target constraints, generated files). Display text is a separate, lossy, escaped rendering that never feeds identity or execution.
- D-029 identity, D-031 launch-owned CMOS fields, D-033 profiles, write policy and the two-drive engine path are unchanged. No `engine/` change is expected; if one is needed, stop and return it to Fable.
**Non-goals:** the self-boot JFD cluster, HD/quad-density media, ARM3/RiscPC titles, multi-disc sets (5b), auto-clicking icon-bar applications, writable-scrap provisioning, running the disc's root `!Boot`.
**Acceptance criteria**
- AC-1 Entry tolerance: new-directory names keep top-bit bytes (including 0xA0); a control byte terminates; attribute bits 6–7 are ignored and reported once per load; old-directory attribute bits are read from all their byte positions regardless of name length; extents are validated only for objects actually read. One odd or irrelevant entry never fails a directory.
- AC-2 Candidate state: every root `!`-directory is `application` (non-directory `!Run` found), `not-application`, or `unknown` (its directory could not be inspected); each also records whether a non-directory `!Boot` exists. A leaf containing 0x20, 0x7F, `.` `:` `*` `#` `$` `&` `@` `^` `%` `\` is kept for diagnostics but is not launchable. Duplicate or ASCII-case-equivalent root leaves, or duplicate `!Run`/`!Boot` children, make the affected candidate non-launchable even by explicit selection and its state `unknown`.
- AC-3 Auto selection order: (0) helper-only discs select nothing; (1) exactly one non-helper application and no `unknown` → select; (2) disc-label rule as today, ASCII-only, and only when exactly one candidate among applications **and** unknowns can match and that one is a verified application; (3) AC-5. Otherwise the existing ambiguity/incomplete OSD and `arcdroid_launch` override apply. Explicit selection of any launchable candidate, helpers included, still works.
- AC-4 Reason reporting: a recognised self-boot disc reports `disc boots itself` ahead of `inspection incomplete`; Auto never mounts the helper for it; explicit selection on a self-boot disc keeps today's behaviour.
- AC-5 (**Founder-gated**) Helper vocabulary, exact ASCII case-insensitive leaf match: `!Install`, `!Installer`, `!ReadMe`, `!Read_Me`, `!ReadMe_HD`, `!Help`, `!SysMerge`, `!Manual`, `!Docs`. If exactly one application remains after removing these and no `unknown` exists, Auto selects it. Helpers keep their ordinals. `!RunToRead`, `!SlowA3000` and genuine multi-game discs stay ambiguous.
- AC-6 Serializer: one function produces the byte-exact desktop boot file. Every path is `ADFS::0.$.<leaf>` (the disc label is no longer used for addressing), double-quoted, leaf bytes raw except `|`→`||`, `"`→`|"`, `<`→`|<`; every generated command is `%`-prefixed so sibling-defined aliases cannot capture it. A leaf that cannot be represented is refused with a specific reason, never altered.
- AC-7 Environment: the boot file issues `Filer_Boot` for `!System`, `!Fonts`, `!Scrap` when present (case-insensitive), then for every other root `!`-directory that has a `!Boot`, in root order, then for the target, then `Dir`/`URD` to `ADFS::0.$`, then `Filer_Run` of the target. No cap below the root-directory bound, no delays, no window opening, no retries. The launch file may span several sectors: the helper-disc builder allocates contiguous sectors for the real size and the resulting image satisfies *free + allocated = declared disc size with non-overlapping extents*, checked by an independent parser in the tests at the maximum boot-list size.
- AC-8 Binding (D-031): versioned format holding ordinal, raw target bytes as hex and the candidate fingerprint; strict full-consumption parser; v1 files are read as today and rewritten only on reselection. Absence is established only by a successful listing of the binding directory that lacks the file; any other failure refuses with a specific reason and never replaces a binding. Refusal only when the selected ordinal's raw target differs from the bound one.
- AC-9 Diagnostics: one escaping function for log and OSD (printable ASCII as is, everything else `\xHH`, quote and backslash escaped, bounded) used for disc label, candidates and decision.
- AC-10 Fixtures/tests (generated from source, L/D/E and through JFD): top-bit and hard-space names, full 10-byte names, stale padding, short old-directory names, attr `0x88`, irrelevant malformed entries, unknown competitors, conflicting names, invalid map/sector bounds, singleton helper, label-matching helper-only disc, two-game disc, every ordinal-change case, legacy binding, malformed/trailing binding, unreadable binding; byte-literal serializer expectations including `|`, `"`, `<`, combinations, top-bit and 0xA0. Sanitizer job covers the new parser paths with the existing mutation approach. The Windows RetroArch job loads one top-bit-name launch fixture.
- AC-11 Synthetic guest applications in a fixture disc: siblings whose `!Boot` records order/count and sets a variable, a target whose `!Run` requires it, a sibling whose `!Boot` errors, one that attempts a write, and one that redefines `Dir`/`Filer_Run` aliases. CI proves image bytes and discovery only (the test ROM has no Filer).
