## Slice 6a work order (Fable, 2026-09-21, S18; Founder decision F-1 = D-049; Astra challenge PROCEED WITH CHANGES, adjudicated in D-050)
**Objective (PRD FR-10, D-049).** When the user has supplied the ADFFS package, a single-disc JASPP JFD whose boot script is available boots through the real ADFFS module inside the guest (`*ADFMount <file>` + `*ADFBootFloppy`), so JASPP's maintained per-title script runs. Without a usable package everything behaves exactly as today. ADFFS is closed, carries no licence text and is **never redistributable**: it is user-supplied like firmware and no byte of it may enter the repository, CI, logs, PRs, releases or any host file ArcDroid writes.

**Verified facts to build on (S17–S18 host probes; RISC OS 3.11, 4096 KiB; details under "JFD / ADFFS evidence").** The ADFFS 2.88 IOC module and its four prerequisite modules run unchanged in the guest; ADFFS reads the image as a *file*, holds it in guest RAM and takes over ADFS drive 0; drive 1 stays readable afterwards (directory listing and file contents verified); any open file or CSD/URD/Lib on drive 0 at mount time yields `Please insert disc`; the launcher must not print (`Echo` opens a blocking command window); `ADFBootFloppy` selects its script by JFD header id (u16 disc number at +12, u16 disc count at +14, u32 game id at +16; key `F%05u%02u` = game id, disc number), preferring the member of that name inside the package's `obey` zip over the JFD-embedded script (`obey_length` at +312); with neither it only simulates Shift-Break.

**Scope.**
1. **Package (C-1).** Location: `<system>/arcdroid/adffs/` — the zip exactly as downloaded (any `*.zip`; if several, the byte-wise lowest file name that validates; logged). Read through the libretro VFS with a small project-authored zip reader on the already-linked zlib: central-directory driven, stored + deflate only, CRC-32 verified, bounded (archive ≤ 8 MiB, ≤ 1024 entries, member ≤ 2 MiB inflated, total inflated for used members ≤ 4 MiB), reject encryption, zip64, data-descriptor-only sizes that disagree, duplicate or case-colliding used names, and any inconsistency between local and central headers. Members are matched by exact name against the allowlist; archive names are never used as host paths and never interpolated into guest commands. RISC OS load/exec/attr come from the `AC` (0x4341) extra field with the `ARC0` signature; a used member without it invalidates the package.
   - **Runtime members (fingerprinted, profile `adffs-2.88-ioc`):** `!ADFFS/ADFFS` `23256f9c…8e77cae`, `!ADFFS/SetVars` `266617cf…9571b831`, `!ADFFS/3rdParty/CLib` `2935eaa8…acf9d849`, `!ADFFS/3rdParty/CallASWI` `a73f88ea…440a27fa`, `!ADFFS/3rdParty/ZLib` `6a012e8f…3e668e07`, `!ADFFS/3rdParty/BootCmds` `96bb091e…c0f0efdc` (full SHA-256 values in "JFD / ADFFS evidence"). A package whose runtime members all match a known profile is **verified**. Any other package is **untested**: used only when the new core option `ADFFS package` = `Allow untested` (default `Verified only`).
   - **Data members (structural validation only):** `!ADFFS/obey` (itself a zip, same reader and limits; members named `F` + 7 digits) and the resource bundle `!ADFFS/trackers/*` except `TimPlayer` and `!Help`, `!ADFFS/extras/{JoyMod,LZWD,LZWD103}`. The bundle is **all or nothing**: every allowlisted member present in the zip is carried; if the carried set does not fit the launch disc the package is invalid (never truncate).
2. **Eligibility (C-2) — decided before launch discovery/chooser; every condition must hold, otherwise the native path runs bit-for-bit as today.** Content is exactly one image (no folder set, no playlist with > 1 entry) and it is a JFD with header disc number = 1 and disc count = 1 and a non-zero game id or an embedded script; core options `JFD boot` (new: `Auto` default | `Native`) = `Auto` and `Launch` = `Auto`; firmware is RISC OS 3.11 (the only OS validated); package valid and (verified or allowed); a script exists (built-in member or embedded, built-in preferred — ArcDroid does not choose, ADFFS does; the core only needs to know one exists and to read its text for the next check); **every `ADFFS:<path>` reference in that script text (case-insensitive, `.`-separated) names a carried member** (`obey.*` references excepted: they need only exist inside `obey`); the JFD *file* fits the carrier (scope 3) and its decoded size ≤ 2048 KiB.
   - One log line per load: `JFD boot: path=adffs script=builtin|embedded profile=<name>|untested version="<module help version>"` or `JFD boot: path=native reason=<not-jfd|multi-image|multi-disc|option|launch-option|os|no-package|invalid-package:<why>|untested-package|no-script|missing-resource:<member>|too-large|decoded-too-large>`.
   - On-screen notice (existing message mechanism, once per load) for: `no-package` with an embedded script ("This image carries a JASPP boot script; place the ADFFS zip in <system>/arcdroid/adffs to use it"); `no-package` otherwise for a JFD with a game id ("may boot better with ADFFS …"); `invalid-package`, `untested-package`, `missing-resource`, `too-large`, `decoded-too-large` (short reason). No notice for the other reasons.
   - The ADFFS path neither reads nor writes `.choice`/`.bind` records and shows no chooser. `Launch` ≠ `Auto` keeps its existing meaning (native).
3. **Guest media (C-3), both memory-backed, read-only, never written to host storage.** Drive 0 = a synthesised 800 K D-format FileCore disc (old map, new directories, every object on a 1024-byte boundary — platform fact from Slice 5a) holding the user's JFD **file bytes verbatim** as one file `$.Game` with file type `&FCE`. Drive 1 = a synthesised 800 K D-format disc holding `$.!ADFFS` (the carried members in their package-relative places, RISC OS metadata from the zip) and the project-authored launcher. Add a bounded memory-backed raw-media source beneath the engine wrapper's existing sector interface (the JFD path is already memory-backed); both discs are write-protected regardless of the `Disk Writes` option and are released on unload and on failed start. The native path keeps today's persisted 640 K L-format launch disc bit-for-bit, and the existing `<save>/arcdroid/media` staging of the user's own image is unchanged (out of scope).
4. **Launcher (C-4; project-authored text — do not copy ADFFS's `!Run`/`!Boot`/`!Loader`).** Started by the existing desktop boot mechanism from drive 1. Required behaviour, in order: no text output; `ADFFS$Dir`/`ADFFS$Path` → `ADFS::1.$.!ADFFS`; run `SetVars`; `ADFFS$FileSizeLimit` 2048; aliases the scripts rely on — `StoreCSD` (remember current filing system + CSD in `ADFFS$CSD`), `RestoreCSD` (restore it), `ADFClipScreen` and `ADFScreenBorders` → `ADFDoNothing`; `ADFFS$JIT` = 0, `ADFFS$CRC` = 0; `ADFFS$LCDGM` unset; load `CLib` only when the ROM's SharedCLibrary is older than 5.17, then `CallASWI`, `ZLib`, `BootCmds`, then the module, each guarded so a failure is a guest error box naming the step; `ADFMount ADFS::0.$.Game`; select ADFS, `NoDir`, `NoLib`, `NoURD`, `Dismount :0`; `ADFBootFloppy`. The launcher must leave no open file and no current directory on drive 0 and must not depend on a RAM disc. If, in Fable's private run, anything on drive 1 proves unusable after the mount, the fallback is the proven RAM-disc variant — keep the ADFFS directory a single substitutable value in the launcher generator.
5. **Session semantics (C-5).** Content identity (D-029/D-041), CMOS seed/normalisation (D-031), `.srm`, options and AV behaviour unchanged. During an ADFFS session the disk-control getters stay truthful (1 image, inserted, index 0) and every state-changing callback (`set_eject_state`, `set_image_index`, `replace_image_index`, `add_image_index`) returns `false` without touching media; reset re-runs the same decision and rebuilds both discs; a failed preflight falls back to native **before** the guest starts; after the guest has started there is no automatic fallback.
6. **Docs.** `docs/` user note (where to put the zip, that ArcDroid is not affiliated with JASPP and does not distribute ADFFS, link to the JASPP forum thread `viewtopic.php?t=722`, the two new options, the single-disc limit, no write-back). Release notes owed: the two options and the notices.

**Non-goals.** Multi-disc/folder-set/playlist titles under ADFFS and ADFFS disc-change hotkeys; write-back (`ADFFlush`/`ADFSave`) or any persistence of the mounted image; JFDs larger than the 800 K carrier and F-format carriers; RISC OS other than 3.11; honouring JFD header flags; the clean-room command layer (former Option A); ADF/APD/HFE through ADFFS; save states; changes to the engine's FDC/JFD reader; changes to existing media staging.

**Affected interfaces.** New core unit(s) for the zip reader, package validation and D-format synthesis (`core/`), eligibility hook ahead of `arc_launch_discover` use in `libretro/arcdroid_libretro.c`, engine-wrapper media source (`engine/arcdroid_engine.[ch]` only — no edits to upstream Arculator files beyond what the JFD memory path already required; if one is unavoidable, stop and return the decision), core options table, `tests/generate_fixtures.py` (synthetic package + JFDs), CMake/test lists, Windows/Android build lists.

The second stage is the launcher proper with `ADFFS$Dir`/`ADFFS$Path` = `RAM::0.$.!ADFFS`. Both synthesised floppies stay read-only and memory-backed; nothing else in scope 3/5 changes.
