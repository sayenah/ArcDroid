## Slice 12a work order — launch discovery: self-boot rule and nested applications (G1 + G2)
**Objective.** Two structural gaps in launch discovery leave five library titles at a dead boot or on the desktop. **G1:** a disc whose boot option is non-zero but which has no root `!Boot` object is treated as "disc boots itself", so nothing runs (idx 22, 133; boot option 3 with one root application each). **G2:** discs whose applications live one directory below the root have no root candidate, so discovery reports "no candidates" (idx 41, 44, 56: 11 applications under 7 plain root directories). Both are fixed by general rules of disc structure — no names, no title knowledge (D-039, Founder S33). Governing: PRD P-3, FR-24, FR-49, FR-52; D-030, D-031, D-033, D-038, D-039, D-042, D-047, D-073, D-087.

**Verified state (S34, `main` `f512cfc`).** `arc_launch_discover` (`core/launch_discovery.c`) reads the root directory only. A candidate is any root directory whose name starts with `!` (`arc_candidate_name`); it is `launchable` when its leaf passes `arc_candidate_launchable` (length ≤ 10, no byte ≤ 0x20 or 0x7f, none of `. : * # $ & @ ^ % \ | " <`); APPLICATION when the directory holds exactly one `!Run` file, NOT_APPLICATION otherwise, UNKNOWN when unreadable or of unexpected size; duplicate `!Run`/`!Boot` → not launchable; a root name equal (ASCII case-insensitive) to any other root object → UNKNOWN (`:1112`). `!System`/`!Fonts`/`!Scrap` are `resource` (never targets, D-042). Decision order: `boot_option != 0` → DISC_BOOTS_ITSELF (`:1134`, before any candidate check; the adapter then publishes no helper and RISC OS boots drive 0 with the disc's own boot option); no candidates → NO_CANDIDATES; no applications/unknowns → NO_APPLICATIONS; one application and no unknowns → SINGLE_APPLICATION; disc-name match; else AMBIGUOUS / INSPECTION_INCOMPLETE (chooser when ≥ 1 verified target on image 1, D-047; the incomplete-inspection warning is a chooser banner only, `core/launch_chooser.c:169`, `:327`; explicit picks `libretro/arcdroid_libretro.c:3737` and remembered choices `:3786` bypass it). **Scope.**
C-1 **Self-boot rule (G1).** With `Launch: Auto`, a disc "boots itself" only when its boot option is non-zero **and** the fully read root directory holds an object named `!Boot` (ASCII case-insensitive), file **or** directory — the rule honours the disc's boot mechanism and never inspects the boot object's contents, filetype or OS. Only a proven absence permits ordinary discovery (candidates, single application, disc-name match, chooser, explicit `Application N`); an unreadable root stays unreadable and duplicate `!Boot` entries keep the boot. Boot option 0, `Launch: Off` and explicit picks are unchanged. When the helper is the boot drive the disc's own boot option never runs (as today for explicit choices). `boot_option` stays reported.
C-2 **Nested applications (G2).** After complete root enumeration, when the root holds **no `!` directory at all** (no application, resource, non-application or unknown `!` directory), discovery inspects each plain root directory for its immediate `!` directory children; it never descends into applications, resources or deeper plain directories, so targets are only `$.!App` or `$.Parent.!App`. Each nested `!` directory is a candidate with `parent` = the root directory's name, classified exactly as at root (one non-directory `!Run` → APPLICATION; malformed/unreadable → UNKNOWN; duplicate control files → not launchable); a nested leaf equal (ASCII case-insensitive) to any other object in its parent → UNKNOWN, not launchable; a parent whose name equals any other root object (directory or file, ASCII case-insensitive) is **ambiguous**: all its children are not launchable and none of their boot commands is emitted, but they still count towards ambiguity/incompleteness (never a false uniqueness); the three D-042 resource names are resources one level down too (initialised, never targets, never ordinals). Root layouts with any `!` directory (incl. 141, resource-only and unknown-only roots) keep today's discovery, numbering, fingerprints and helper serialization, except for the separately specified G1 decision change.
 **Bounds.** A global candidate limit of 77 counting every classification; order = root-entry order, then child-entry order; at most one root read, 77 parent reads and 77 candidate-directory reads (155 directory reads of ≤ 2 KiB); no unbounded tree. Unreadable parents and candidates omitted by the limit are tracked separately from `unknown_count`; when any parent is unreadable or the limit truncates the scan, automatic uniqueness and the disc-name match are suppressed and the outcome is INSPECTION_INCOMPLETE (verified targets remain available to the chooser and to explicit picks); a truncated scan is never presented as complete. `Application N` (D-031) numbers candidates in discovery order skipping resources only; the eight-option limit stays; the chooser exposes all verified targets. The disc-name match compares application leaves (existing normalisation) across the discovered set; equal matching leaves under different parents stay ambiguous.
C-3 **Addressing** *(amended by D-088 / run 2: no wildcard addresses; a parent is addressable only when representable and unique; otherwise its candidates are never launchable).* A target's identity is its raw components (optional parent, leaf); its command-line address is computed at launch preparation from the mounted media and never persisted. A nested target is addressed as `ADFS::0.$.<parent>.<leaf>`. **Every** parent address must identify exactly one root object, which must be the intended directory (C-2's ambiguity rule). The parent is emitted literally when every byte passes the leaf representability rule minus the leading-`!` requirement; otherwise only its longest non-empty **command-safe ASCII** prefix (stopping before the first unsafe or extended byte ≥ 0x80) plus one trailing `*`, and only when the complete root namespace was enumerated and that pattern matches exactly one root object — files **and** directories, `*` also matching zero characters (a file named exactly the prefix is a collision), under deterministic ASCII case folding (case-only collisions fail). No safe address → the candidate is not launchable (still counted for ambiguity; refusal/notice "candidate N parent is not representable"); never emit unsafe raw bytes, speculative escaping, a bare `*`, or a first-match pick. `%Dir`/`%URD` stay `ADFS::0.$`. **Initialisation for a nested target** stays local to its parent: the D-042 resources inside that parent in the existing resource order, then that parent's other bootable siblings in discovery order, then the target — each operand through the same checked component serializer; applications in other parents are not booted. Root helper bytes are unchanged for unchanged inputs; the script size check stays.
C-4 **Records and identity.** Existing root formats are preserved exactly: `.choice` v1 (`desktop`/`app`) and v2 (install) records and `.bind` v1/v2 keep their bytes, are still emitted for root targets, and legacy leaf records mean **root targets only**. Nested targets use new native formats `.choice` v3 and `.bind` v3 with separately hex-encoded, length-bounded parent and leaf components (each ≤ 10 bytes), the desktop semantics and the install discriminator preserved; a v3 record matches only a currently verified, addressable candidate with the same raw parent and leaf; an explicit binding refuses ordinal retargeting even when the leaf matches. The root candidate fingerprint bytes (order, states, flags) are unchanged; a nested discovery uses a domain-separated fingerprint over component lengths/bytes, candidate order, state, launchable/addressable and boot flags, and scan completeness. Replay keeps today's policy (no new global fingerprint-equality requirement). Strict parsing, trailing-byte rejection, bounded reads, atomic publication and preservation of existing records on failure as today; maximum record sizes recomputed from the grammar. `ArcLaunchPlan.launch_target` carries the leaf for root targets (spelling unchanged) and the full raw relative path `<parent>.<leaf>` for nested targets (capacity ≥ 22 bytes incl. terminator); production and test-profile matching (`core/input_mapping.c`, the adapter) compare the same value; a root-only constraint never matches a nested application; the generated wildcard is never an identity. Content identity (D-029) unchanged.
C-5 **Diagnostics.** `Launch:` keeps its prefix and every existing root spelling and adds `root-boot=yes|no`, `scope=root|nested`, `scan=complete|incomplete` and the underlying discovery reason independently of the final action (chooser shown/remembered); candidates and the decision render as escaped full identities `<parent>.<leaf>`; the wildcard address is logged separately from identity; list truncation is marked with total counts; the incomplete status survives final-action logging. Chooser rows show `Parent.!App` with escaped bytes; a focused label is always shown complete (two-line rows or equivalent). Notices: none for a successful G1 recovery; **one non-blocking incomplete-inspection notice** whenever a verified target launches from an incomplete nested scan without the chooser banner (explicit pick or remembered replay — the selection stays permitted, no fingerprint invalidation, no re-choice); concise frontend notices for an unsafe address, an incomplete scan without usable targets, and helper-publication failure; `Application N` is never suggested for an unsafe target or beyond eight. Scripts, labels, records and logs are explicitly bounded.
