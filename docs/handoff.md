## Slice 26 work order — automatic insertion of a requested disc (D-105 → D-113)

**Objective / governing requirement.** When a game asks for another disc of the loaded multi-image set, ArcDroid inserts that disc automatically and shows a short notice (Founder D-113; D-073 pick-up-and-play; PRD P-4 general mechanisms only). Two general signals, no per-title data: **A** — FileCore asks for a disc by name; **B** — the game's own lookup of a fully qualified floppy path fails and the object exists on exactly one other image. A core option reduces it to a hint or turns it off.

**Verified evidence (S48 private probes, RISC OS 3.11, real boot; S48 scratchpad `s48/d105/`, ledger `s48/LEDGER.md`).** 65 of 218 library zips are multi-image sets. No title polls the drive while its prompt waits. **A**: 20, 65, 96, 200 — a user-mode file operation on `adfs::<name>.…` makes FileCore issue `OS_UpCall` 2 (MediaNotKnown) from ROM in SVC, R1 = 8 (ADFS), R2 → the disc name, R3 = -1, R4 = iteration, R5 = 100 cs, repeating each second; inserting the image with that FileCore disc name ends it within 1–3 iterations and the operation completes (20's `XOS_Find` returns a handle). **B**: polling 26, 81, 89, 115, 173 and per-acknowledgement 30, 42 look up fully qualified `adfs::0.…`/`ADFS::0.…` paths; authenticated outcomes at the caller's continuation (one guarded per-instruction check while armed; ≈ 9 500 lookups, 0 abandoned): catalogue reads (`OS_File` 5/17) return R0 = 0 with V clear when not found, `XOS_File` 255 loads return V set with error number exactly **&D6** ("File '…' not found"); inserting the requested image alone takes 89/81 into gameplay, 26/173 to their next screen, 115 to its own disc-3 request; 30 and 42-class titles proceed on their next acknowledgement. A swap with emulated time between eject and insert made the guest see **&108D3 "Drive empty"** (81) — the swap must be zero-time. Negatives: 97 and 118 make one cross-disc lookup in normal play; 23 repeats a lookup whose object is not on disc 2 at that path. Out of v1 (unauthenticated filesystem binding): 68/69 (`$.TRACKS.N`, unqualified), 49 (`:0.…`), variable-relative names (12, 36, 71). No title in the B cohort calls `Wimp_Poll`/`Wimp_PollIdle` in its request window. `File$Path` is not set in a launched session (no `OS_SetVarVal`).

**Astra** (thread `01a0f904-f1e2-76d3-afee-4d360d70e789`, S48 scratchpad `s48/astra26/`): stage 1 (Blocker: result attribution at SVC→USR; 8 High) → 2 DO NOT PROCEED (backing-image absence ≠ guest failure; search paths; unqualified-path authority; burst rule; insertion point) → 3 DO NOT PROCEED (A/B precedence; unqualified forms UNKNOWN; B liveness; context invariants) → 4 DO NOT PROCEED (polling starvation; task isolation) → 5 **PROCEED WITH CHANGES** (operation/object-type compatibility). ### Scope (C-1 … C-9)
- **C-1 Request observer (engine; pure module beside `engine/arc_error_box.c`, fed from `arc_engine_boot_watch_swi`).** SWI numbers normalised (X bit `0x20000` ignored). Guest memory is read only through bounded, side-effect-free reads of RAM/ROM pages (never I/O space); unreadable → ignore.
  - **A**: `OS_UpCall` with R0 = 1 (MediaNotPresent) or 2 (MediaNotKnown), issued in SVC from ROM, R1 = the ADFS filing-system number, R3 = -1 or 0, R2 → a name of 1–10 printable characters (validated, bounded). It starts or continues an A episode keyed by the name; `OS_UpCall` 4 (MediaSearchEnd), a media change or reset ends it. A validated A request supersedes and discards any pending B watch/observation/trigger.
  - **B lookups**: from a **user-mode** caller (RAM or ROM): `OS_File` reasons 5, 13, 15, 17, 20, 21, 22, 23 (catalogue), 12, 14, 16, 255 (load); `OS_Find` opens of existing objects (`&4x`, `&Cx`; never `&8x`, never close). The filename must be **fully qualified on the floppy** (C-2) or the lookup is ignored. On entry: capture the name, resolve it (C-3) synchronously on the non-inserted images through a glue-registered callback, and arm a **continuation watch** {continuation = SWI address + 4, entry user R13}. While armed, every user-mode instruction is checked **before it executes**: the watch completes only at the exact continuation with the entry R13 (outcome registers sampled then); any other user-mode instruction (error handler, callback, anything) discards it permanently; a new SWI entry of the observed classes before completion also discards it. Outcome **not found** iff (catalogue read: V clear, R0 = 0) or (load or open: V set and the error number at [R0] is exactly &D6) or (`OS_Find`: V clear, R0 = 0). Any other outcome (found, other errors incl. &108D3, unreadable error block) → no observation.
  - **Observation** = not-found outcome **and** the resolution result: the object is present on exactly one non-inserted image with a type compatible with the operation (catalogue: file or directory; load: file only; open: file, or directory only when the open's flags accept directories), and no image resolved UNKNOWN.
  - **Repetition identity** = (canonical object, continuation address, entry R13). The trigger is the **second** observation of the same identity within one episode. Accumulation is cleared on: the object found; any media change, manual disk-control action, reset, option change; entry (any mode) of `Wimp_Poll`, `Wimp_PollIdle`, `Wimp_Initialise`, `Wimp_CloseDown`, `Wimp_StartTask`, `OS_Exit`, `OS_ChangeEnvironment`; 120 s emulated without a matching observation. Different objects never combine.
- **C-2 Admitted names (v1).** `adfs::0.<path>` (ADFS name in any letter case) and `adfs::<discname>.<path>` only when `<discname>` equals the inserted image's FileCore disc name (case-insensitive ASCII). `<path>` = `$` or `$.`-rooted plain components. Everything else is UNKNOWN and never observed: other drives, `:0.`, unqualified names, `@ ^ & % \`, `<variable>` names, path lists, wildcards (`#`, `*`), names naming a disc other than the inserted one (left to A), special fields. Names are compared byte-preserving with ASCII-only case folding; component length within the format's limit.
- **C-3 Resolver (core, new public API beside `arc_directory_read` in `core/launch_discovery.c` or a sibling file).** Resolve a canonical `$`-rooted path on a prepared image → `FILE` / `DIR` / `ABSENT` / `UNKNOWN`, reusing the existing map/directory validation (old/new map, L ordering, D/E/F, JFD sector access) and FileCore disc-name reading. UNKNOWN for unsupported/corrupt structures, limits, unreadable bytes. Bounded depth, components and allocations. Results for non-inserted images use their **effective view** (Disk Writes store contents, JFD presentation options) and are cached per (image, media/store generation, canonical path), invalidated on writes, replacement, reset and option change. At most the inserted JFD plus one transiently decoded other JFD live at a time; sets up to 32 images (`core/playlist.h:9`). Disc names of every prepared image are available for A (JFD re-parse as `arc_boot_media_digest` does).
- **C-4 Decision.** **A**: exactly one prepared image other than the inserted one carries the requested disc name → candidate; zero or several → nothing. **B**: the C-1 trigger names its candidate. Only on the native path (ADFFS active → nothing; hint mode shows nothing either), only for sets with ≥ 2 prepared images.
- **C-5 Commit (insertion transaction).**
  - **B** is committed **synchronously at the triggering continuation** (before that instruction executes; no yield, no emulated time, no frame split): the engine calls the glue-registered commit handler. **A** is committed at the next frame boundary while its episode is active (FileCore is waiting in its media loop).
  - Preconditions at commit (any failing → the trigger is discarded, not deferred; A retries at the next boundary while its episode lasts): option Auto; floppy controller idle (no WD1770 command, no 82C711 command/result phase, no pending FDC timer); no B watch pending except the one completing (B) / none (A, after supersession); no Slice 25 invocation ready; chooser/install helper not active; native path; candidate still valid (generations unchanged).
  - Transaction: preflight the candidate (prepared, readable, store healthy, machine accepts the media) **before** ejecting; then eject → select index → insert **with no emulated time in between**, reusing the existing disk-control internals (store ownership, JFD refresh, cancellations, `ioc_discchange`); on failure restore the previous mount and index where possible, else a truthful ejected state and a failure notice. The notice is queued only after success and shown by the glue at the next frame. Manual eject/index/replace invalidates any queued work. `set_initial_image` stays NULL.
- **C-6 Ownership and reset.** A successful automatic insertion records ownership {launch image index (kept across a chain of automatic insertions), current index}. `retro_reset` re-inserts the launch image while ownership holds; any manual disk-control action clears ownership (today's reset behaviour then applies).
- **C-7 Option and anti-thrash.** New option `arcdroid_disc_requests` "Disc Requests": `auto` "Insert automatically" (default) / `hint` "Hint only" / `off` "Off", applied live (Off cancels pending work). Hint mode uses the same evidence and leaves media untouched. After an automatic insertion, a request whose candidate is the previously inserted image within 10 s emulated becomes a hint for that episode (forward chains such as disc 2 → disc 3 are allowed). One notice per episode, rate-limited. Note the base option count changes (`_Static_assert`s, `tests/windows_load_harness.c` option count — Slice 24 lesson).
- **C-8 Notices and logs.** Auto: `Disc N inserted` (one-based native index); Hint: `Insert disc N with Disk Control`; failure: `Disc N could not be inserted`. Through the existing notice path with the legacy fallback. Log lines (INFO): `Disc request: signal=A name=<name> candidate=<N|none|ambiguous> action=<inserted|hint|ignored> reason=<…>` and `Disc request: signal=B object=<canonical> candidate=<N> observation=<1|2> action=<…> reason=<…>`; DEBUG for discarded watches.
- **C-9 Docs.** `docs/release-notes-slice26.md` (what, the option, the notice, limits: unqualified/`:0.`/variable names, Wimp-polling tasks, ADFFS path, per-acknowledgement titles need one extra acknowledgement, 68/69/49 not covered).

### Non-goals
Unqualified, `:0.`, variable-relative or search-path names (needs authenticated filesystem binding — later slice); game-drawn prompts without a lookup; icon-bar launchers that wait after the disc arrives (96/200, D-085); the ADFFS path; any synthesized input or acknowledgement; changes to Slice 25; RetroArch-side UI.
