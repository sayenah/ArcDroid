## Rulings (recorded in D-195)
- **R-e0-1 Endpoint stop and its proof.** The endpoint mode stops CPU execution at exactly the ordinal and with the drain semantics of today's intrusive mode, with integer batching and fast begin/end live. Sol chooses (i) a per-batch bound at batch admission so no batch crosses `measure_last` (an explicit, test-only exception to the "no quota or batch-size change" non-goal, active only while an endpoint is armed) or (ii) an in-batch ordinal check. Either applies at **every** interpreter entry, including the `NULL`-batch path (`arm.c:1963` area, which never calls `batch_next`). Either mechanism must show, by a disassembly or instruction-count comparison of the unarmed hot loop against the pinned base, that it adds no unarmed per-instruction work; an inactive-flag test alone does not establish that. Three comparisons are required (AC-1).
- **R-e0-2 §2.2 classes.** Endpoint arming state, the captured interval and any pending-capture or previous-completion state the mode introduces are **measurement state** (compared). Exercise counters, profile counters and cross-check bookkeeping are **host-only, excluded**, reset at every G-13 point, and kept **outside** `m` and `arc_rpc_mem_fast` (no masking of the raw snapshot). The measurement statics today live outside the raw snapshot (`rpc_mem_timing.c:55-66`), so a separate, explicit comparison covers them (AC-3).
- **R-e0-3 Counter ownership.** 1a-0 owns (a) the re-rank "(add)" ranking counters as 6b-P0i profile hooks (profile JSON schema 2; schema pin updated); (b) the exercise-counter facility, readable in every TEST_FAULTS core including the calibration core, reported through getters or runner stderr, never stdout traces; integer/rational counts appear in both. M1 (6b-P0j) keeps churn, write-then-execute, code DACR class, code-slot evictions by data installs, E1 direct/indirect, bus transitions per instruction, admission factors and the C-0 ledger, and cites 1a-0's service classes, TLB walks and integer/rational counters.
- **R-e0-4 Build-capability matrix and macro split.** 1a-0 may split today's TEST_FAULTS into a test-API/plan part and a hot-path test-hook part so a **measurement core** can exist. The matrix (frozen in the design note) names for each of shipping, ordinary test/calibration, plan, profile/cross-check and measurement builds which hooks and APIs exist. In the measurement core: per-event trace counting stays (a declared exception, per event, not per instruction; it keeps the runner's stdout complete); the intrusive measure mode, observer tracing, the test quota clamp and allocation-fault injection are absent, and their APIs **refuse explicitly** (the runner reports the refusal and exits non-zero), never succeed as no-ops. Ordinary TEST_FAULTS targets keep every current capability. The frame timer (`core_ns` from the test `retro_run` wrapper, `arcdroid_engine.c:123`) is kept and validated in the measurement core.
- **R-e0-5 Frozen benefit rule** — AC-8, fixed before any A/A collection.

## Scope
1. **Endpoint measurement mode** (test-only). Arming by `(first, last, drained)` as for `arc_rpc_mem_measure`. Semantics, stated in the design note as equations before code:
   - **start** = completion tick of instruction `first−1` (as the intrusive mode captures at `rpc_mem_timing.c:282-289`), not `first`'s issue tick minus a base. Video holds, idle/wake and intervening service may sit between them, so the mode preserves that completion in measurement state when it occurs, without updating canonical timing state to take a measurement.
   - **end (non-drained)** = completion of instruction `last` (request-free: its issue tick; with requests: as `commands()`/shortcut completion today).
   - **end (drained)** = the tick at which the last packet retires with `!m.count && !m.bcount` after instruction `last` has completed, including when `last` is request-free and older buffered writes are still draining (today's guard at `:645` keys on `m.stats.instructions`, which fast request-free completion does not update).
   - Interval stats (words, fills, packets, hits, fetch hits, instructions) defined over the same span as the intrusive mode.
   The intrusive mode stays unchanged as the independent check, and its request-level unit tests keep using it.
2. **Calibrations in both modes.** `rpc-memory-timing-0..3` run every interval in both modes; both equal the oracle, and the **full interval record** of the two modes is compared field by field (today's checks compare mainly duration and instruction delta, `tests/rpc_timing_test.c:57`).
3. **Exercise counters** (kind ii), with units, denominators, increment points and eligibility predicates documented: integer-batched instructions and rational continuations in all three instantiations; reference-path opportunities for each future fast path — L1: lookups that hit beyond way 0, with probe counts, separate from empty-cache returns and searched misses; S1: entries meeting the full S1 predicate (`!pending`, `!video_active`, `cycle_active`, valid finish, `now < due < min(finish, boundary)`); B3: memory-region fill packets counted **after commit**, separately from attempted and rolled-back shortcut work; A1/F1: data/fetch TLB tag hits, and separately the accesses that also pass permission with no pending abort (only the latter are fast-path opportunities).
4. **Ranking counters** (kind i, profile schema 2): lookups per instruction with hit way and probes per hit (access and maintenance callers separate; empty, miss and hit distinguished); `batch_service` entries in **exclusive** classes — pending; busy-not-pending and S1-eligible; busy-not-pending, not eligible; due ≥ finish (only where finish is valid); video active — with the nesting stated; AL share; data and fetch TLB walks per instruction; fill packets per instruction split fetch/data and memory/ROM; shortcut commits and rollbacks; integer/rational instruction counts.
5. **Cross-check facility** (`ARCDROID_RPC_CROSSCHECK`, requires the test macros, off by default): a small reporting and self-test contract for later slices — each later fast path compares its result with the retained reference over the §2.2 fields Astra stage 1 finding 3 names, counts mismatches, fails the run on any mismatch with the field named, reports on stderr. Path-specific isolation belongs to each later slice. Enabled in the existing sanitizer CI job; 1a-0's only client is the self-test.
6. **Measurement core** (R-e0-4): a non-installed core target for host, MinGW and Android, usable by `rpc_runner` with plans; export, symbol and Windows test-export guards apply; build and Odin3 commands documented in `tools/rpc-r1-runbook.md`.
7. **Authored synthetic workloads** for AC-8, committed as reproducible plans with named generator arguments (extending `tools/rpc_hot_workload.py` or a sibling): warm load/store, SA-110 streaming stores, ARM710 streaming stores, LDM/STM8; plus the existing hot workload.
8. **Docs:** invariants §2.2 (R-e0-2), refreshed citations at the new head (grounding C8 list), G-12 text for the endpoint mode; the capability matrix and endpoint equations in the design note; `docs/riscpc-translator.md` measurement section.

## Non-goals
Any fast path (L1, S1, B3, A1, F1, D1/D2); shipping defaults, rate, quota or batch size (except R-e0-1(i)'s armed-only test bound); M1's counters; the rational continuation table; `.info` changes.

## Acceptance criteria
- **AC-1 Three comparisons.** (a) **Endpoint vs intrusive:** identical full interval records and stop/drain behaviour for all 4,677 calibration intervals. (b) **Endpoint armed vs unarmed:** identical guest execution through the functional completion of instruction `last` (traces compared up to that point), on goldens and observation plans. (c) **Unarmed candidate vs pinned base:** all 25 goldens, `rpc-hot-throughput`, `rpc-observation-plan` (quotas 1/7/200 × off/unmatched/trace/active, `integer_attempts > 0`), equivalence tests and the raw inspector memcmp unchanged. On host, ASan/UBSan, MinGW and Android. Goldens never regenerated.
- **AC-2 Directed endpoint matrix.** Directed cases with known answers: `first == last`; `first` = the first instruction; endpoints on both sides of quota boundaries (1, 7, 200); `first` immediately after a video hold and after idle/wake; final instruction request-free vs requesting, each drained and non-drained, including request-free last with older buffered writes active; shortcut commit and rollback at the endpoint; driver issue exactly at the limit; integer→service and rational continuation across the endpoint; the `NULL`-batch path. Endpoint mutants committed and killed: stale previous completion, issue-plus-base start, premature drained capture, one extra instruction, lost fractional ticks, capture-induced flush, missing `NULL`-batch stop. A per-model table of integer-batched instructions, rational continuations and S1-eligible entries inside measured intervals; every counter that can be nonzero for that model (by rate and clock) is nonzero; structural zeros listed with reasons.
- **AC-3 State classes.** A test that changing any measurement field (including new pending-capture state) is detected by the measurement-state comparison, and that changing an excluded counter is not detected by either it or the raw snapshot; counters reset at every G-13 point.
- **AC-4 Counters.** Each exercise and ranking counter checked on a directed case with a known answer (way-k hit with known probes; empty-cache lookup; searched miss; each service class; a valid-finish and an invalid-finish entry; memory vs ROM fill; shortcut commit and rollback; data and fetch TLB walk; tag hit with permission failure; tag hit with pending abort; denied install). Mutants (drop each increment, swap data/fetch, swap classes, count before commit, count at the wrong boundary) committed and killed.
- **AC-5 Shipping unchanged and measurement shipping-shaped.** (a) Every shipping object's code sections byte-identical before and after on host, MinGW and Android (section names per platform). (b) Measurement vs shipping, same optimisation and visibility: a named set of hot functions (the three `arm.c` instantiations, `arc_rpc_mem_batch_service`, `arc_rpc_mem_access`, `checked_translation`, `getpccache`, the inline timing helpers' callers) compared in code, relocations and constants, and the shared structure layouts (`ArcRpcMemFast` and the timing state) compared, allowing only the enumerated per-event diagnostic exception; done by a committed script. (c) The measurement core runs the hot and 031 plans; its stdout traces and guest instruction counts equal the plan core's for the same plans; `core_ns` timing present and plausible; refused requests (intrusive measure, observer trace, quota clamp, fault injection) fail explicitly. (d) Ordinary TEST_FAULTS targets keep their capabilities: the forced-slow request-level tests (`rpc-memory-service-boundaries`, `rpc-fetch-memo-eligibility`, `rpc-memory-hot-video-boundaries`, `rpc-memory-long-*`) run and pass.
- **AC-6 Cross-check facility.** An injected mismatch fails the run naming the field; the sanitizer CI job builds with it on and passes; stdout traces unchanged.
- **AC-7 Mutant suites and guards.** `rpc-qa-mutations`, `rpc-observation-mutants`, `rpc-observers-mutants`, `rpc-profile-mutants` pass with anchors ported where lines moved; import, include-closure, symbol, frontend-boundary and export guards pass.
- **AC-8 Frozen benefit rule (for every later 1a slice) and its A/A band (Fable's private legs).**
  - **Deciding core:** the 1a-0 measurement core (Odin3: Android Release build; Windows: native MinGW). Observer configuration as shipped at the base, no watch live, trace off.
  - **Workloads and windows:** hot (D-181 recipe: realtime 60 s warm + 300 s measured); the four AC-8 synthetics (same timing); 031 under the AC-10 recipe (S61 inputs, fresh store copy per run, 8000 frames, decision window frames 6400–7400; 6000–8000 reported). 031 is the representative 3D title; a second 3D title is profiled in M1, not a decision workload.
  - **Sequence:** two orders of six runs each, order 1 = A B B A A B, order 2 = B A A B B A; 120 s idle between runs; RetroArch closed; screen on; battery temperature and CPU frequencies recorded before each run. Odin3 runs are serial (D-182).
  - **Statistics:** per run, p50 and p95 of frame `core_ns` over the window; per order, the median of the three A runs and of the three B runs; Δ = (B − A)/A for p50 and p95.
  - **Band:** from 1a-0's A/A legs (base against itself under two tags), per workload, band₅₀ = max over both orders of |Δp50| and band₉₅ = max |Δp95|, each floored at 0.5 %.
  - **Clock-step exclusion:** per run, split the window into ten equal blocks and take each block's p50; a run is flagged if three or more consecutive blocks differ from the run's median block by more than 8 % while the adjacent runs of the same binary in that order show no such shift. A flagged run is re-run once in the same slot. If the re-run is also flagged, or flags occur in two or more runs of the same binary in one order, they are not excluded: the comparison is reported with them, and flags only in the candidate count as candidate-induced.
  - **Outcomes:** **gain** — Δp50 ≤ −band₅₀ in both orders and no regression; **regression** — Δp50 > +band₅₀ or Δp95 > +band₉₅ in both orders, on any workload; **retest** — the orders disagree; one full retest of that workload; **inconclusive** — still disagreeing after the retest; an inconclusive or no-gain slice is not merged on benefit grounds (the draft's drop rule). Windows: no-regression criterion only, same statistics against its own A/A band, on hot and 031.
- **AC-9 D-180 baseline (D-194 scope).** On the measurement core: observed-active vs unobserved ≤ 3 % at p50 and p95 on the hot workload with no watch, and on 031 (observers off vs production cells) — the two gates; held-watch, SWI-dense and idle-desktop ratios recorded as upper bounds, not gated. This is Phase 1a's cumulative D-180 baseline (3 % total on the integrated tree). Fable's private legs.
- **AC-10 Ranking report (Fable).** Profile-schema-2 report on 031 and on the hot workload run on ARM710, from which Fable records the L1/S1 order (re-rank rule in `docs/riscpc-6b-phase1a.md`) before 1a-2/1a-3 work orders.
- **AC-11 Provenance.** Edits under `engine/rpcemu/` carry dated ArcDroid modification notices; UPSTREAM.md/manifest lineage satisfies `check-rpcemu-import.py`; new headers in `PROJECT_HEADERS`; new externs `arc_rpc_`-prefixed in `rpc_namespace.h` and `backend-symbols.json`; no ROM, title or trace bytes committed.
